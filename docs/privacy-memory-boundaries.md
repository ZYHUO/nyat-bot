# 记忆读取的来源边界

QQ 与 Telegram 共用检索流程，但不共用会话权限。数字相同不代表相同的人或群；QQ 内部 ID 必须在身份表中找到平台、机器人账号和会话映射。不存在或损坏的映射拒绝读取。

同一会话的有效历史仍可检索，包括私聊中的私密记忆。旧数据仅有有效 `chatId` 时，它可作为原会话来源；缺失来源、非法来源、`chatId` 与 `sourceChatId` 冲突、显式平台或账号矛盾的记录均不注入。

长期向量记忆的边界仍是整个会话或群；Telegram 论坛群内的不同话题不会在这一层单独隔离。本轮没有迁移旧向量的话题字段。执行检查点和中期摘要另按话题隔离，详见 [上下文隐私说明](context-privacy.md)。

跨会话检索必须同时满足以下条件：

- 记录明确标记 `public`。
- 记录携带明确的 `sourcePlatform` 与 `sourceAccountId`，与来源映射和目标账号一致。
- 来源不是私聊或配置的敏感群。
- 来源和目标属于同一平台、同一机器人账号。

普通群的 `contextual` 内容不因来自群聊而成为公开资料。历史记录没有平台或账号来源时，不会被自动补标为公开。新写入会保存平台、账号和会话来源；没有追溯修改旧向量，也没有混用不同嵌入模型。

`MEMORY_VISIBILITY_ENABLED` 与 `MEMORY_CROSS_CONTEXT_ENABLED` 仅控制跨会话功能是否启用，不能关闭基础隔离。`DM_AUTO_PRIVATE` 已退役；配置文件中的旧值会被忽略，私聊始终属于私密来源。

CodeAct 的自动长期记忆由 `SUBAGENT_MEMORY_ENABLED` 控制；开启后 `SUBAGENT_MEMORY_CHAT_IDS` 为空表示全部会话可用，非空仅对列出的会话生效。它始终调用同源检索入口，并保留相关度下限、数量与字符预算，不因此共享其他会话的记忆。

人物画像按会话读取。合并摘要必须能证明全部输入来源均可在目标会话读取；一份摘要含其他群或私聊的上下文内容时，不会因模型声称已经概括而解除限制。私聊称呼不再作为其他群的默认称呼；群内可单独设置自己的称呼。

经验检索通过来源 episode 的 `chat_id` 过滤，并在排序、截断和使用次数记账之前完成。孤立经验或缺少查询会话的请求返回空结果，保留原记录供审计。

这些是读取边界，并不意味着每条历史内容都适合原样发出；最终发送仍需遵守输出侧的敏感信息规则。
