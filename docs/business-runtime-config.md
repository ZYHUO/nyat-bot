# 主人确认的日记业务配置

业务设置不需要改 env 或重启模型进程。新增入口只管理每个来源会话的两个布尔值：
`enabled`（是否写日记）、`publishToSource`（是否把结果发回来源会话）。
目录、cron、模型路由、secret、主人身份及安全开关仍由运维配置。

首次安装需要正常应用 [新增迁移](../migrations/0133_business_config.sql)，并由运维设置：

```dotenv
BUSINESS_CONFIG_ENABLED=true
BUSINESS_CONFIG_CHAT_IDS=42,-1001234567890
```

默认关闭，空名单拒绝全部。名单必须同时包含发起配置的主人私聊和被配置的来源会话。
Telegram 使用真实 chat ID；QQ 使用现有身份表映射的内部 ID，不能填原始 QQ 群号。
QQ 主人只能配置同平台、同账号会话；Telegram 主人身份不能替代 QQ 主人身份。
其他人的私聊不能成为配置来源。

主人在私聊提出「开启这个群的日记，写好发回群里」后，Meta 可调用
`journal.config(sourceChatId)` 查看当前设置、修订号及最近十次历史，再调用
`journal.previewConfig({sourceChatId, patch:{enabled:true,publishToSource:true}})`。
预览返回修改前后设置和一条完整确认命令。机器人把命令交给主人直接发送；
收到命令时配置立即生效。模型只有读取和预览能力，没有提交配置的 RPC。
该确认边界防止后台唤醒、转发内容或检索材料被误当作主人当前授权。

例如当前修订号为 0 时：

```text
/journal_config {"operation":"patch","sourceChatId":-1001234567890,"expectedRevision":0,"patch":{"enabled":true,"publishToSource":true}}
/journal_config show -1001234567890
```

确认命令必须是主人私聊直接发送、五分钟内的新消息；拒绝编辑、转发、机器人代发和匿名身份。
入口在 Telegram/QQ 共享 ingress 的去重之后、Meta/legacy 分流之前执行。旧队列、自然语言命令路由
和模型生成的命令文本不能直接提交设置。带 @bot 后缀时必须匹配实际机器人用户名。

配置与审计保存在同一个 SQLite 事务中，每次更改追加一个不可变修订，记录操作者、
来源、命令消息 ID、时间及前后值。`expectedRevision` 不匹配会拒绝，要求重新预览；
同一消息重试不会重复更改。历史不自动清理。回退也追加修订，不删除日记或覆盖数据库：

修订、历史、回退和命令去重均绑定来源及控制者的平台、公开账号 ID。保留数据库切换到另一个
Telegram bot 时，旧账号的运行时授权不会自动继承，新账号从自己的修订号 0 开始确认；
相同消息 ID 不会与旧账号冲突。仅轮换同一 bot 的 token secret 不影响其配置，审计不保存 token。

```text
/journal_config {"operation":"rollback","sourceChatId":-1001234567890,"expectedRevision":1,"revision":0}
```

`revision:0` 恢复第一次修改前的快照。可以回到其他较旧修订；当前状态和历史可用 show 查询。
撤销旧主人或控制会话权限后，旧设置失效为关闭状态；新授权主人仍可在原修订上显式更正。

日记写入和定时任务每次重新读取配置。现有 UTC cron 时间继续由运维管理，开启业务配置后
在 `CRON_ENABLED=true` 时注册这些时间点，即使 env 中日记总开关原本关闭，也可通过运行时配置启用指定来源。
写入前及发布前重新检查修订，期间配置发生变化则放弃尚未执行的步骤。
同一进程、同一来源同时写作会被拒绝，防止 cron/Meta/作息触发相互覆盖。

配置频道只代表「该频道的资料生成该频道日记并发回该频道」，不会把主人私聊或别群资料
转发进去。原有带来源标签的日记文件继续隔离，旧的未知来源文件不被自动读取或清理。
没有频道消息证据时可以返回 no_evidence，这不是跨会话收集资料的授权。

此实现依赖现有单一 SQLite/文件状态 authority。不能让多台 bot 写入各自独立数据库，
也没有提供多机日记文件锁或数据库复制。计算节点不应启用此控制入口。
已提交给平台的发送不能因稍后的关闭命令撤销；发送结果未知时本次流程不会自动重发。
崩溃时恰好一次发送、跨机故障切换及不同 schema 的代码回退仍需要独立验证。
新增迁移需先在停写窗口由运维安装；A/B 控制器不能把有状态迁移当作普通代码热更新。
