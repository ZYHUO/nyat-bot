# 联通记忆与披露范围

记得一件事、知道自己与谁在哪个群相处过、能够把原文告诉当前对象，是三个不同的判断。旧版把群目录也套上了正文的会话限制，主人私聊查询其他群时得到空结果，模型还可能把“查不到”误说成“不在群”。本轮把群关系查询和内容检索分开，保留事实来源，不把所有聊天重新标成公开。

## 群关系

`chats.find(群名片段)` 返回 `groups`、`coverage`、`status` 和解释，而非无说明的空数组。每条关系带平台、账号、核验时间、成员状态及证据类型。`member` 表示核验时是成员；`not_member` 仅来自明确的平台成员回执。接口出错、候选索引不全、没有权限、名称没有命中都不是“不在群”的证据。

Telegram 只能从已知群 ID 中核查，Bot API 不能列出所有已加入的群，因此覆盖范围始终注明 `known_only`。历史索引只提供候选；必须用当前机器人核验成员关系和群名。QQ 使用已经认证的当前 OneBot 客户端获取群列表，不再把 QQ 群 ID 发给 Telegram。

主人私聊可查看授权账号的机器人群目录。其他私聊不获得此目录，群内查询只返回当前群，连其他群的数量也不返回。群目录是元数据，不会解锁该群的原文、成员资料、转发或跨群发送。

## 主人本人记忆

授权依据是宿主绑定的当前会话：TG 私聊必须是配置的 `MASTER_UID`；QQ 必须解析到当前 `ONEBOT_ACCOUNT_ID` 下的 `ONEBOT_OWNER_ID` 私聊。昵称相同、裸数字相同、模型指定目标 UID 都不能建立身份联系。

默认各平台分别识别自己的主人。只有部署者确认两端属于同一人并设置 `OWNER_MEMORY_LINK_ENABLED=true`，才联通这两个身份。开关不改变群聊的披露权限，也不会把不同平台的管理员默认合并。

自动长期记忆及 `memory.search`、针对主人本人的 `memory.recallPerson` 使用同一授权规则：

- 可以读取主人本人在群里的发言，以及其自身私聊中来源可靠的主人与机器人对话。
- 不读取其他人的私聊，不推测群内某条机器人回复一定是说给主人的，不开放所有群的完整上下文。
- 敏感会话仍受限制；结果逐条携带平台、账号、来源会话和可见性。当前会话与另一端相同的 message ID 不会被误认为同一条。
- 明确属于另一个机器人账号的记录保持原来源，不能冒认为当前账号的经历。
- 来源账号缺失的旧 Telegram 记录，仅主人本人发言可以作为“历史 Telegram／账号未知”使用；不能以此认领旧机器人回复或声称自己当前在该群。

模型得到的是当前对象可接收的记录，不是所有私聊全文再靠提示词保密。群聊、其他人的私聊仍走原有严格路径；主人私聊的压缩摘要、续跑检查点也不会回流群里。密钥和令牌等输出拦截继续保留。

例如，主人问“为什么不在赣江院说话”，机器人应先核验群关系，明确区分“在群”“不在群”和“尚无法确认”。是否在群不等于知道沉默的原因；没有活动或决策证据时应如实说不知道，不能指责用户记混了。继续问“我之前说过什么”时，可检索这个主人本人已授权的发言，不能顺带展示其他人的私聊。
