# dispatch gate 职责边界重评

> 2026-09-18。问题：dispatch gate 拦掉 79% 的 heart reply，这些拦截里
> 哪些是"该拦的物理节奏"，哪些是"该交给模型的判断"？

## 一、gate 的实际行为（实测，非推断）

近 6 小时的 dispatch gate 分布：
```
191  Meta autoDispatch: dispatch gate suppressed
101  dispatch gate: no_action
 90  dispatch gate: defer → scheduled re-eval
 47  gate talk-value below threshold, defer
  4  dispatch gate: continue
```
**433 次调用里只有 4 次走到"真决定"，其余全是短路**（cooldown / talk-value）。

## 二、gate 的 LLM 分支：121/122 给出同一个答案

`Timing gate decision` 日志（122 次真实 LLM 决定）：
```
action: {'no_action': 121, 'continue': 1}
延迟 中位: 2194 ms
```

理由分布**高度同质**：
```
10  未提及我，话题无关，不硬挤
 9  当前群聊无@我、无针对我的对话，话题与我无关，无需参与
 3  未@我，话题与我无关，无需参与
 3  群友正聊网络优化相关话题，未提及我，无需参与
 3  群友密集讨论相关话题，未提及我，无合适切入点
 2  群内讨论VNC技术问题，未被@且无接梗/答疑点，保持安静
...
```

**121 次里绝大多数是同一个判断：「没提到我、话题无关、别硬挤」。**

## 三、根因：这不是判断，是规则

`prompts/task/timing-gate.md` 的判断清单里明写：
```
3. 群友们彼此在聊、不是在跟我聊 → no_action，别硬挤。
```
121/122 的决定**正是命中这条规则**。

所以 gate 的 LLM 调用在做的是**规则匹配**，不是取舍判断——
**而这正是 NyatOS 要取代的东西。** 每次 2.2 秒 + 一次 LLM 调用，
换来一个可以写成 if 的结论。

## 四、但对照实验暴露了真正的问题

我用同样的输入喂单决策点（NyatOS）：
| 输入 | gate | NyatOS |
|---|---|---|
| 家宽怎么优化 / 换个线路试试 | no_action | **speak**「作为群成员可以凑过去关心」 |
| VNC 连不上 / 端口没开吧 | no_action | **speak**「可以提供力所能及的帮助」 |
| 机票报销怎么弄 / 找财务 | no_action | **speak**「刚好知道流程，可以回答」 |

**NyatOS 在 gate 说"别硬挤"的三个场景上全部选择了插话。**

这与 Phase 2.3 的负面结果**是同一件事**：
- gate 有"别硬挤"的**克制规则**
- NyatOS 没有，且它的 prompt 说"真人刷群时大多数消息是划过去的"，
  但在**技术讨论**这类内容上它仍然想参与

## 五、结论：删除 gate 的 LLM 分支是安全的，但**必须先解决 eagerness**

### 可以删（有充分证据）
```
gate.ts 的 LLM 调用（callWithFallback × 2 次重试）
prompts/task/timing-gate.md（2,920 字符）
```
理由：
1. 121/122 输出同一个结论，且该结论由 prompt 里的**显式规则**决定
2. 每次 2.2 秒延迟 + LLM 成本，换来可写成 if 的结果
3. 它与 NyatOS 的单决策点**功能重叠**

### 不能删（物理节奏，与内容判断无关）
```
cooldown 短路（191 次 suppressed 的主要来源）
talk-value 攒批（47 次 defer）
wait + 到点恢复
```
理由：这些是**调度**，不产生"该不该说"的判断。删了就是纯成本上升。

### ⚠️ 删除的前置条件
**必须先让 NyatOS 学会克制，否则删掉 gate 的 LLM 会让插话率暴涨。**

证据：同一批输入，NyatOS 想说 3/3，gate 说 0/3。
这不是"NyatOS 更好"，是**它更爱说话**——而 Phase 2.3 已经证明它停不下来
（48 次/28 分钟，中位间隔 7 秒，告知无效）。

### 修正后的路线
1. **先做**：给 NyatOS 的 prompt 加上"别硬挤"这一层**判断依据**
   （不是规则，是让它理解"群友彼此在聊"意味着什么）
2. **再验证**：同一批 gate 说 no_action 的输入，NyatOS 是否也能说 silent
3. **然后才删** gate 的 LLM 分支

**在 1-2 完成前删 gate 的 LLM，等于用一个爱插话的组件替换一个克制的组件。**

---

## 六、步骤 1 已做，但**验证失败**（诚实记录）

### 做了什么
`ConversationField` 其实已经算好了 `addresseeEdges`（谁在跟谁说话）和 `floorOwner`，
但 **Frame 从来没渲染它们**。已补上：
```
[谁在跟谁说话] 群友之间在互相接话，没人把话递给你。
[谁在跟谁说话] 有人把话递给你了。
```
这是**事实**，不是规则——把 gate 那条"别硬挤"的规则背后的信息，
以事实形式交给模型，让它自己得出结论。

### 验证结果：**没有解决 eagerness**

| 输入 | gate | NyatOS（加了事实后） |
|---|---|---|
| 家宽怎么优化 / 换个线路试试 | no_action | **speak**「补充实用优化建议」 |
| VNC 连不上 / 端口没开吧 | no_action | **speak**「我可以提供帮助」 |
| 机票报销怎么弄 / 找财务 | no_action | **speak**「主动搭话符合场景」 |
| @bot 帮我看下（对照） | continue | speak ✓ |

**同一批输入，gate 说 0/3 该说，NyatOS 说 3/3 想说。**

### 结论：删 gate 的 LLM 这个动作，**前提条件未满足**

`[谁在跟谁说话]` 这条事实是**必要信息**（模型现在能看到结构了），
但**不是充分条件**——它看到"没人把话递给你"，仍然选择插话。

这与 Phase 2.3 的负面结果一致：**NyatOS 的 eagerness 不是信息缺失导致的，
是它的判断倾向**。它认为"群友在讨论技术问题、我可以提供帮助"就该说话——
这是一个**价值判断差异**，不是事实缺失。

### 所以路线要再修正

原路线"步骤 1（加事实）→ 2（验证）→ 3（删 gate LLM）"在第 2 步**卡住了**。

可选路径：
- **A. 保留 gate 的 LLM**，承认它做的"别硬挤"判断是 NyatOS 目前做不到的
- **B. 把 gate 的"别硬挤"改成显式事实/参数**（例如把"参与度"作为可配置的人格维度）
- **C. 接受更高的插话率**，用额度（6/小时）兜底，观察用户反应

**我倾向 A**：gate 的 LLM 每次 2.2 秒确实浪费（121/122 同一个答案），
但它给出的答案是对的，而 NyatOS 目前给不出。
**在 NyatOS 证明自己能克制之前，删掉它是拿正确性换成本。**

### 可以立刻做的成本优化（不损失正确性）
既然 121/122 都命中"别硬挤"这条规则，**把这条规则从 LLM 判断改成确定性前置检查**
是安全的：
```
if (没有 @bot && addresseeEdges 全部指向他人 && 话题与 bot 无关)
  → no_action（0ms，不烧 LLM）
```
这样 121 次里的绝大多数变成 0 成本，**保留 LLM 只用于真正模糊的情况**。
这是"删掉 99% 的浪费，保留 1% 的判断力"。
