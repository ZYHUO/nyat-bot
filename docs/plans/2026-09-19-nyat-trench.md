## 摘要

NyatBot 今天有 **五个地方**在回答同一个问题——"现在该不该说话"——其中三个已被它们自己的实测数据证明不携带信息。我们提议把这个问题**从代码里删掉**，交给模型；同时把宿主里唯一一个本该存在、实际却是死代码的东西**变成真的**：一个不可绕过的物理边界。

新架构叫**海沟（Nyat Trench）**。核心论断一句话：

> **模型负责"想说什么、说不说"，宿主只负责"你的嗓子现在什么状态"。**
> 今天 1,754 行 timing gate 把宿主的读数伪装成了模型的裁决；
> 今天 `canSpeakActively()` 这个本该存在的硬闸有零个调用方。

> **实现状态（round 67 自查，提交前最后一项）**：上面这句话到今天为止是
> **一半真、一半假**——
>
> **已实现并在生产运行**：L0 海床（P/θ 有界积分器 + 时间泵 + 睡眠积压 + 定向债 +
> 卡死自恢复）、L1 沟壁（发送前硬闸 + 包络 + 出站守卫 + 锚点去重）、L2 反射
> （Echo 学习闭环）。
>
> **未实现**：L3 皮层、L4 洋流（论文 §三 的五层表里列了，代码里不存在）。
> **未执行**：任何代码删除 —— 七个子系统一个都没删，只有两个做成了
> 一行可开关的候选（`META_HEART_BYPASS_CHAT_IDS` / `TIMING_GATE_LLM_ENABLED`）。
>
> 而更重要的是：**"模型负责想说什么、说不说"这句话，生产里至今不成立。**
> 实测有四条路径能在不问模型的情况下产生发送（Meta heart 的放行、same_speaker_burst、
> post-task continuation、direct-L0），而单决策点想 speak 96.8%、心流放行 7.7%。
> 这不是实现没做完——这是**论文的论断与系统现状之间的差距**，
> 也是 Phase 1 要付的代价（§八 已注明 reply 侧可能倒贴）。
>
> 所以这篇论文的正确读法是：**一份已完成 3/5 层、附完整失败记录与实测修正的设计文档**，
> 不是一份"新架构已上线"的报告。

这不是"更聪明的 gate"，是取消 gate 这个范畴。我们先用两节证明它非换不可，再给出替代物、逐项对账（一条不丢）、以及可证伪的验收标准。

## 一、为什么必须换：四条实测证据

### 1.1 五层判定，三层无信息

| 层 | 位置 | 生产实测 | 判定 |
|---|---|---|---|
| L0 确定性规则 | `judge/rules.ts` | 103 条真实回放证明 `at_others` 真有命中 | **保留**（事实提取） |
| L1 / L2 AI 判定 | `judge/{micro,judge}.ts` | 4 天 **1 次**命中 | ~~纯故障回退，死~~ **保留为故障回退**（见注 1） |
| Heart | `pipeline/heart/` + `meta/heart-adapter.ts` | **两套并行**：1,046 次/天 + 2,083 次/天；`lost arm race — silence` 235 次 | ~~两套都杀~~ **Meta heart 是主抑制层，旁路=拔抑制器**（见注 2） |
| Timing gate LLM | `timing/gate.ts` | 125 次判定 **124 次 no_action**，理由清一色是同一条规则的改写；另有 **199 次解析失败 fail-closed** | ~~死~~ **一行开关可关，未删**（见注 3） |
| NyatOS 单决策点 | `nyatos/shadow.ts` | 近 6 小时 **226 speak / 2 wait / 0 silent** | 只记录，不执行 |


> **注 1**（round 14）：L1/L2 是纯故障回退没错，但它是 judge 唯一的安全网。
> "死"的意思是"平时不工作"，不是"可以删"——删了 L0 漏判时无路可走。
>
> **注 2**（round 54/61）：事前我把 heart 定性成"既当泵又当作者，角色混淆"，
> 计划只留定时触发。**实测它是这个仓库实际做抑制的那层**（12,009 次/天，放行 7.7%），
> 而且旁路它之后仍有三条路径绕过它产生任务（§九·补四）。"两套都杀"因此是
> 未执行的计划，不是已验证的结论。
>
> **注 3**（round 40）：主张成立的实测依据（61% 解析失败 + 99% 复述一条规则）
> 仍然有效，但我把它做成了 `TIMING_GATE_LLM_ENABLED` 一行开关而非删除——
> 因为删它会让 legacy 路径多说约 27 条/天，而我没有对照组。

**"要不要说"这个问题被问了五遍，答案却分裂**：单决策点想说话，线上闭嘴，而 190 条配对样本里 **155 次是"想说却没说"**。这不是某个层写错了——是**判断与表达被切成两次独立调用**的结构必然。

### 1.2 那个我们以为有的硬闸，是死代码

`src/nyatos/budget.ts` 定义了 `canSpeakActively()`——"一条主动发言现在允不允许发"。

```
$ grep -rn "canSpeakActively" src/ --include='*.ts'
src/nyatos/budget.ts:163:  export async function canSpeakActively(...)
```

**全仓库唯一一次出现是它自己的定义。零调用方。**

今天实际执行"每小时 6 条 + 90 秒间距"的是 `spendParticipation()` / `markActiveSpeech()`——它们在 `host-api.ts:1055` 和 `deliver.ts:1452` 被调用，**位置在发送之后**，且是 fire-and-forget 的计数。模型能看到的只有 Frame 里一句劝告性的"你刚说过话"。

**结论：防刷屏的物理上限，今天既不在发送前，也不是硬闸。它是事后记账加一句忠告。**

### 1.3 这个仓库已经做过"删掉 gate"的实验，并且失败了

`budget.ts` 头部记录着 NyatOS Phase 2.3 的负结果（2026-09-18，54 样本影子运行）：

- 28 分钟内单决策点想发言 **48 次**
- 相邻 speak 的间隔中位数 **7 秒**（47 个间隔里 42 个 < 60 秒）
- 同期线上真实发送 **0 条**
- 决定性实验：把"你过去 2 分钟发了 4 条、3 条没人理"作为**纯事实**告诉模型——**它仍然选择说**

四轮调查排除了 token 截断、帧渲染、prompt 框架、self-history 缺失。该注释自己的结论：

> 旧 cooldown 在做两件事，只有一件是错的：**决定什么值得说**（应交给模型）；**阻止 runaway 自我重复**（不能信任模型）。

**这是本文最重要的前提**：任何"删掉物理约束、全靠模型自觉"的方案，都是把这个已经做过并失败的实验用新词汇再写一遍。讨论会里认知论派的提案初稿正是如此，红队在第二轮用这一段把它驳回——**这不是观点分歧，是复测结论。**

### 1.4 规模：要砍的是什么

七个子系统去重后 **33,688 行**。但其中与"要不要说"直接相关的只有 judge 819 + timing 1,754 + heart 1,197 = **3,770 行（11.2%）**。剩下 88.8% 是**功能代码**（签到/抽卡/游戏/多模态/DM relay/命令分发）与**事故补丁**。

> **23,491 行 pipeline 里有一部分不是架构，是六起生产事故的尸检报告。**
> ——红队成员 D

所以"完全替代七个子系统"这个提法需要被精确化：**要删的是 3,770 行判定编排 + 约 21,000 行把隐式业务分支写成代码的部分；要搬的是功能代码；要扶正的是事故补丁。**

### 2.2 第二轮：互相咬合后剩下的东西

红队终审给出关键发现（后经验证）：**综合方案不满足三条否决项中的两条半**——缺发送前硬闸、缺"到点恢复"的幂等证明、缺三角计数与单消息 token 顶。

认知论派在防守轮**全盘接受红队约束**，并说出本轮最重要的一句话：

> **单子提议，身体处置（Physics only）。**
> "删掉决策编排"删的是 host 里的裁判层；红队的五条不是编排，是骨骼。
> 单子负责可变，身体负责不变——**这两件事本来就是同一件事的两面。**

仲裁成员则把度量衡掰正：

> **风险的单位不是"删了多少行"，是"新增了多少个不可回滚的机制"。**
> 删除一秒 revert，新增机制一旦上线就改变后续所有输入。

于是第一期只新增 **两个有界标量**（P 与 E），其余全是删除与无状态搬运——**因此可以拿 A/B 的野心砍掉六成代码，同时守住 C 的纪律：每个切片当天上线、隔天回滚。**

## 三、新架构：Nyat Trench（海沟）

不选"潮"选"沟"：潮是周期性、不可钳制的；**沟是有硬壁的、深度有限的、可抽干的**。红队的四条物理要求（有界 / 可观测 / 可强制复位 / 失败泄压）长在"沟"这个形状上。

```
            ┌─────────────────────────────┐
   L4 洋流  │  subagent：无状态探索，用完即焚 │  Current   ← 未建
            ├─────────────────────────────┤
   L3 皮层  │  meta(想) + reply(说)        │  Cortex   ← 未建（现有 meta/reply 原样保留）
            ├─────────────────────────────┤
   L2 反射  │  judge(判定) + Echo(唯一学习) │  Reflex   ← ✅ 已建（echo.ts）
            ├─────────────────────────────┤
   L1 沟壁  │  wall：路由/预算/超时/clamp  │  Wall     ← ✅ 已建（envelope.ts + 发送前硬闸）
            ├─────────────────────────────┤
   L0 海床  │  trench：P/θ + 泵 + 硬复位   │  Bed      ← ✅ 已建（trench.ts，另加睡眠积压/定向债/卡死恢复）
            └─────────────────────────────┘
```

**新人验收一句话：只有 L0 有记忆，只有 L2 会学；L1 只会说"不"，L3 只会说"是"，L4 用完即焚。**

| 层 | 唯一职责 | 明确禁止 | 可触状态 |
|---|---|---|---|
| L0 海床 | 把"过去发生过什么"压成两个有界标量，只回一个读数 | 不得判断、不得提创意、不得调用任何模型 | **P, θ（唯一写入方）** |
| L1 沟壁 | 确定性骨架：路由、预算、超时、串行化、强制泄压 | 不得写业务判断、不得生成内容 | 无（只读 P） |
| L2 反射 | 判定与结果配对，产出全系统唯一可学信号 | 不得自由解释、不得为解释调模型 | **E（唯一写入方）** |
| L3 皮层 | 叙事生成与下一步计划 | 不得写 P/θ/E、不得持有跨会话可变状态 | 无（只读） |
| L4 洋流 | 无状态外包探索，回收有界报告 | 不得持有长期状态、不得自有循环 | 无 |

### 3.1 控制流

```
Telegram update
   ▼
L1 神经节：归一化 · 去重 · 事实提取（今天的 L0 规则降级为"读数"）
   → 产出连续量 salience，不产任何裁决
   ▼
L1 沟壁·预算段：路由（命令/事务先行，永不进脑子）
   ▼
L0 海床读数：P, θ, E → 渲染成 Frame 事实行（"这一个小时你已经说了 3 条"）
   ▼
L2 醒觉裁决：salience × P/θ 是否值得付一次 LLM
   低于阈值 → 记一条"在场（潜水）"，不花 token
   ▼
L3 一转 ★唯一一次 LLM 调用★
   输入 = Frame（场 + 内感 + 身体能力 + 自身历史 + 时钟 + 牵挂 + 群风俗）
   输出 = 一组 Act：speak / 滑过去 / observe / remember / act(办事) / 约自己 / react / 翻篇
   ★ 判断与措辞在同一次思考里完成 ★
   ▼
L1 沟壁·发送闸（唯一出口）：
   出站文本守卫 → 预算硬闸(canSpeakActively 复活) → 90s 间距 →
   语义重复 → 字面自复读 → 同锚点一次 → 身份/上下文校验 → token 硬顶
   命中 → 把"撞到什么"作为事实回灌，同一转重开（≤1 次）
   ▼
L3 发声器：typing.beforeMs 打字停顿（期间更高 salience 可重开此转）
   ▼
L2 效应器：发送 → 扣预算（**发送前**）→ 落账本（prediction.watchFor + causation_id）
   ▼
L2 反射·Echo：观察窗到期 → 确定性回填 outcome → E 更新 → P += δ
```

### 3.2 三个核心机制

#### 机制一：一转（Turn）——消灭"思考一件事、说另一件事"

今天判断（heart/gate）与表达（reply）是两次独立调用，所以"单决策点想说、线上不说"那道 155/190 的裂缝不是 bug，是架构必然。海沟里**判断和措辞是同一次思考**——一个人身上不可能把这两件事分开。

副效应：每天省掉 heart 1,046 + heart-adapter 2,083 + gate LLM 125 次判定调用。

#### 机制二：气压 P 与岸线 θ（有界积分器）

```
P ∈ [0, 12]        饱和钳制，单调不降直到衰减/复位
θ = 4.0（第一期冻结为常量，单位：次/小时）
r = clamp(θ · g(P), 0.25, 6) 次/小时,  g(P) = 0.35 + 0.65·(P/12)
```

~~**结构性保证（不是调参）**：P=0 时 r ≥ 1.4 次/小时（不会消失）；P=12 时 r ≤ 6（不会吵）。~~

> **2026-09-19 修正（多模型评审第 22 轮查出）**：上面后半句是**空保证**。
> g(12)=0.35+0.65=1.0，θ=4.0 → r(12)=4.0。`R_MAX=6` 在 θ=4.0 时**永不生效**，
> 是死钳。真正的速率上界是 θ 本身，不是夹取。
> 所以正确的表述是：**P=0 时 r=1.4（不会消失）；P=12 时 r=θ=4.0（上界由 θ 决定，
> 不由 clamp 决定）**。这也意味着论文里"学习 θ 是第二期"的排序更要紧：
> 只要 θ 还是冻结常量，系统就只有一条节流：P 的形状。

| 维度 | 旧 timing gate | 新 海床 |
|---|---|---|
| 形态 | 二元闸门（continue/wait/no_action） | 连续标量 + 岸线 |
| 谁持有 | host 判定，模型不知情 | host **只读只写**，模型看得见自己的 P |
| 越界时 | 静默丢弃消息 | **推迟而非丢弃**，模型在 Frame 里看得见自己错过了什么 |
| 失败模式 | fail-closed → 静默塌缩（125 次里 124 次 no_action） | P 持续累积必然越线 + 沉默券 4h 无条件放行 |

三条复位 trigger（全幂等，L2/L3/L4 无权拒绝）：
1. **时间泵**：heart 每 60 分钟 P ← P × 0.5（半衰），写复位记录
2. **事件**：一次交互闭环判定成功 → P ← 0
3. **运维硬复位**：`nyat.physics.reset()` → P←0, θ←4.0, E←0.5，写审计行

单点写入：唯一增量方 = L2-Echo（δ∈[0,1]，一次闭环最多 +1）；唯一衰减方 = 时间泵；唯一硬复位方 = 运维端点。**不存在第二个 setter。**

#### 机制三：Echo（回声）——全系统唯一的学习

```
E ∈ [0.05, 0.90]  硬钳制
E ← clamp(E + 0.15·(y − E), 0.05, 0.90),  初值 0.45
```

四个信号全部宿主可观测、零 token：
- 被接住 `y=1.0`（240 秒内回复/@/reaction，已有）
- 疑似被接住 `y=0.25`（同窗内未指向任何人的消息，纯时序，新增）
- 被无视 `y=0`（ignored_5_msgs，已有）
- 插砸了 `y=−0.5`（发言后两个以上人类开始互相对话绕过 bot，新增，只罚搭话券）

E 驱动两件事：岸线高度 `θ_eff = θ_min + (θ_max−θ_min)·(E*/max(E,E_min))^γ`，与搭话券配给。

**为什么一个标量够用**：仓库已有先例——`src/pipeline/tracking/topic-bandit.ts`（105 行，确定性 ε-greedy，0ms）已在地证明标量够用；`belief-verify.ts`（224 行）证明校验不需要重型模型。而 17 维效用函数需要标签，**我们只有 Echo 能产标签**——把消费者放在生产者前面是因果倒置。

## 四、time gate 的完整替代（逐项对账，一条不丢）

> **逐项审计结论（round 95）**：13 项里 **11 项的承体位在原处完好**
> （1 precheck / 4 talk-value 四函数 / 7 semantic-dup / 8 anti-repeat / 9 泄漏守卫 /
> 10 repliedAnchors / 13 typing.beforeMs），**2 项只做到一半**（2 做成开关未删、
> 3 与 11 指向的 reservation 未建），**1 项的前提被推翻**（5 的 direct 豁免几乎
> 总触发，实际管事的是包络），**1 项不可删**（12 STOP）。

## 六、不可协商的五条物理约束

这是红队给出的、经认知论派全盘接受并形式化的清单。**它们不是编排，是骨骼。**

1. **出站文本守卫**（host 确定性，模型不可绕过）：内部记账格式 / 工具占位符（17 项表 + 通用正则）/ 空文本。理由：1,104 条记账范例就在上下文里，"写给自己看的"与"要说的"在 token 序列层面不可分。这是六类事故里唯一能以近零成本 100% 拦截的一类。
2. **发言物理预算**（host 硬闸，非 Frame 建议）：~~6 条/小时 + 90 秒间距，direct 豁免~~ **由包络接管：被叫到 150 条/小时、主动 100 条/小时**（见注）。理由：§1.3 的决定性实验证明劝告无效；它必须同时是刷屏闸和 token 闸。

   > **注（round 35/37 实测）**：原设计的"6 条/小时 + 90 秒，direct 豁免"是一个
   > **死信**——生产里 100% 的群发送带引用锚点（host 用 `defaultReplyTo` 兜底填），
   > 于是"direct 豁免"几乎总被触发，那 6 条/小时从不拦人。真正在管事的是后来加的
   > 包络（`envelope.ts`，enforce），参数由 3.9 倍投影口径回测得出（150/100 拦 10.7%）。
   > 约束的**意图**（host 硬闸、非 Frame 建议、同时是刷屏闸和 token 闸）不变，
   > 但指定的机制当时是一个空转的闸。
3. **异步唤醒完整消费链**：任何模型排定的未来动作必须有到 host 调度器的真实消费者且幂等。理由：`self_scheduled_wake` 曾有写方零消费方；time gate 的功能完整性 = **该说的时候说得上**。
4. **自锁看门狗 + 时钟单点写入**：任何 host 否决器必须带 liveness 不变量（连续否决 N 次 / T 小时零主动发言即告警并强制解锁），衰减时钟只能被唯一权威方推进。理由：satiation latch 是仓库唯一持续 4 天的静默故障，根因是 `updated_at` 被非权威方刷新。
5. **发送侧身份与锚点校验**：同批次同 targetMessageId 只一次；目标必须是"对我说话的人"；DM 与群上下文不互串。理由：对应两次真实事故，且模型在"我刚戳了哪个 id"上无任何优势。

### 三条一票否决项

新架构若触发任一条，直接枪毙：
- **V1** 无 host 侧、模型不可绕过的出站文本守卫。
- **V2** time gate 只有否决/延迟，没有"到点恢复"的完整链路与幂等证明。验收：衰竭注入测试——同一 job 重放 N 次 / GETDEL 后进程崩溃 / anchor 写入后 transition 失败，三种注入下唤醒既不丢也不重且计数相等。
- **V3** 无（意图 / 执行 / 否决）三角计数器、无两个塌缩方向的量化不变量、无单消息 token 硬顶与降级路径。

## 七、失败模式与可证伪指标

### 7.1 两个塌缩吸引子（为什么简单修复不够）

**静默塌缩** 触发条件（全部已实测）：任何以人类回应率为奖励的学习分量（155/190 基线本就决定梯度指向沉默）；抑制器时钟可被别处刷新（satiation 实测 4 天）；fail-closed 成为默认（gate 125 次里 124 次 no_action——还没引入学习，系统已落进静默吸引子）；沉默不产生 outcome，"正确沉默"与"病态沉默"在账本上同形。

**刷屏塌缩** 触发条件：奖励 = 任何互动（同义 spam 是对"至少得到一次回应"的最优策略）；无硬预算（28 分钟 48 次、告知无效 = 默认值）；自我上下文污染；persona 先验无基线句 = 100% speak。

**统一解释**：prompt 规则是**纯比例控制**，只对当前可见上下文反应、没有记忆项；而六起事故全部是**累积失效**（6 条累积、satiation 累积、4 天累积、1,104 条范例累积）。要么接受一个有界、可观测、可复位的积分器（host 侧物理约束），要么在两个吸引子之间不可见地随机游荡。

海沟用结构而非参数同时封死两端：**一次 speak 抽掉 85% 气压，而 τ=3h 的念头 10 分钟只衰减 4%——抽水速率严格超过填充速率上界，稳态 P 有界，不可能自激**（此句在 round 42 之前是**空话**：`releasePressure` 写好了却没有任何调用方，那 85% 在生产里从未发生。见补二·E）；另一侧沉默券的触发条件是"距上次发送的墙上时间 ≥ 4h"，是关于 `Date.now()` 的单调不减函数，**任何学习量都碰不到它**。

### 7.2 三个 daily 验证指标（零 token，纯 SQL）

1. **沉默塌缩主征兆**：`tide_reservation` 上 `beached/(beached+fired)` per day，目标 <15%。连续两天 >25% ⇒ 抬沉默券频率或降 θ_max，**不动 budget**。附带健康检查：某群 7 天 beached=0 且 fired=0 ⇒ 调度 bug 不是塌缩。
2. **刷屏唯一早期信号**：`self_replies WHERE trigger_uid=0` 分群算 spoke 与 `echo_rate`。**spoke≥6 且 echo_rate<0.20 ⇒ 正在刷屏**。budget 硬顶让 spoke 不可能超 6/h，所以 spoke 高只是必要、echo_rate<0.2 才是充分。
3. **学习信号存活率（元指标）**：`self_replies WHERE trigger_uid=0 AND outcome='unknown'` 占比，目标 <10%。**这是现状最大的洞**（实测 3,337 条里 98.7% 是 unknown），超过 25% 表示 E 学不到任何东西、整套海沟退化成固定阈值 bot，而指标 1/2 会假装健康。

   > **注（round 65）**：这个指标的**分母需要修正**。原式把"无人后续"也算成洞，
   > 但那些消息**结构上不可判**（没人说话 = 没有证据，不是没去判）。
   > 实测近 24h：主动发言 12 条，unknown 10 条（83%），其中
   > **7 条发出后 10 分钟内无任何入站**（真不可判），只有 3 条"本该能判而未判"。
   > 所以 83% 这个数字高估了洞的大小——它在说"群里没人接话"，不在说"E 没学"。
   >
   > 修正后的指标：**可判而未知** 占比（unknown 且发出后 10 分钟内有入站）÷
   > 可判总数（outcome≠unknown 加上面那类）。当前 3/12 = 25%，仍然触线，
   > 但量级从 83% 降到 25%，性质从"系统坏"变成"确实要修"。
   >
   > 附带：指标 1 的数据源 `tide_reservation` **至今未实现**（grep 全仓零命中），
   > 所以"沉默塌缩主征兆"这一项目前**不可计算**。它在论文里看起来是活的，
   > 实际是一个没有数据的指标。

### 7.3 一个尚未解决的深层风险

红队在终审里留下一条**可证伪的反对意见**：海沟保证频率落带内，但不保证带内每条是**对谁说的、该不该说、有多大**。一个每小时 5 条"收到喵"的 bot 会完美通过全部结构约束。

它给出两周可证伪检验：逐条记录 `anchor_ok`（reply 目标 ∈ 本轮 burst 发送者 uid 集）、`size`（>700 字符记超限）、`route_ok`（chatId 符号与来源一致），按触发源分三组（被@ / band 内主动 / beached 触发）。**预言：频率落带内，但 beached 组违规率 ≥ 被@ 组 3 倍。** 反证即红队认输：三组差异 <1.5 倍且总违规率 <2%。

这条检验已被列为第一期的埋点需求——**它不是可选的研究，是验收标准。**

## 九·补、实施四轮后的实测修正（2026-09-19 深夜）

### 补一：给决策点一具身体，**不会**让它变克制（阴性结果）

| 补身体前 | 1675/1732 (96.7%) | 10.1% |
| 补身体后 | 970/972 (99.8%) | 14.2% |

身体事实确实到达了模型眼前——`why` 里开始出现"刚才自己说话没人接有点小无聊""没人理我刚好凑上去搭话"。**但判定没动，speak 比例反而升了。**

它把"没人理我"解读成**再凑一句的理由**，不是收声的理由。

这从反方向复现了 `budget.ts` 头部那个 Phase 2.3 负结果（告诉它"3 条没人理"它仍选择说）。两次独立测量同一个答案，所以它是结论不是噪音：

> **克制必须是物理的（L0 海床 + L1 边界），不能是信息的。**
> 身体事实的价值不在"让它克制"，在"让它能诚实地推理自己"——这是两件事，论文原先混为一谈。

### 补二：Phase 2 的真实缺口是 30%，不是 69%（我的尺子坏了）

论文 Phase 2 以 >85% 一致率为准入。第一版度量用
`self_replies.trigger_msg_id === shadow.messageId` 做 join，得出 **14.2%**。

**那个 join 是错的**：shadow 判的是消息 N，而群里还在流动，等 bot 回复时往往锚在更晚的消息 M 上，trigger_msg_id 根本对不上。一次真实的"判定→执行"被我记成了分歧。

换成"判定后 120 秒内该群有没有 bot 发言"：

| join 方式 | 一致率 |
|---|---|
| messageId 相等 | 14.2% |
| 时间邻域 | **53.3%** |

判定到实际发送的延迟中位 **18 秒**。系统一直在同意我，只是我的尺子读不出来。

**一个错误的测量比没有测量更糟**——它会让接下来三个回合打向错误的目标。`scripts/decision-equivalence.mts` 里现在留着注释说明为什么不能那么 join。

### 补三：投影影响 3.9x，而且**没有物理上界**（这是硬 blocker）

比一致率更诚实的一个数：判定点一旦变成权威，各群发送率会变成多少。

| 群 | 入站 | 发言 | 实际 | 判定点想要 | 放大 |
|---|---|---|---|---|---|
| -1003821093564 | 1219 | 266 | 22% | 86% | **3.9x** |
| -1004451430063 | | | 24% | 86% | 3.6x |
| -1004430867819 | | | 24% | 86% | 3.6x |
| -1004449419602 | | | 35% | 86% | 2.4x |

让这个数变成 blocker 的事实：那个最忙的群 **266 条/天 = 11 条/小时，已经超过 participation budget 的 6 条/小时**。

它超了，是因为生产里 **1572 次群发送全部带引用锚点**，而带锚点 = "有人叫我" = **豁免预算**。

> **我们唯一的物理边界，在承载全部流量的那条路上是个洞。**

所以补一 conclusion 的工程含义才落地：既然克制不能靠信息，而物理边界又只在没车的那条路上，那 Phase 2 的前提就不是"把判定点改聪明"，而是**把边界铺到有车的那条路上**。

### 补四：补上那个洞 —— L1 包络（Envelope）

`src/nyatos/envelope.ts`，管**形状**不管总量：

```
被叫到的： TRENCH_BURST_MAX        (8 条/窗口)
主动的：   TRENCH_BURST_MAX_ACTIVE (3 条/窗口)
```

不对称是设计核心：**五分钟内回 8 个问题是尽职，主动插 8 次话是刷屏**。旧 budget 的"direct 豁免"语义保留为**程度**而非全免。

三态 `TRENCH_ENVELOPE_MODE`：`off`（默认）/ `shadow`（只记录本来会被拦什么）/ `enforce`。当前部署在 shadow —— 因为直接改生产行为之前必须先有数。

接线按本会话反复出现的教训做了测试证明（`tests/unit/subagent/envelope-wiring.test.ts`：host-api 真的会调它 / enforce 真拦 / shadow 真放 / 被拦不记账），并且**同时接到了 tick 路径**——主动发言不走 host-api，这是切片 2b 已经栽过一次的坑。

### 补五：实施顺序被这三条改写

论文 §9 的 Phase 1 是"关掉 Meta heart-adapter"。现在不能这么做，因为：

- Meta heart 12,009 次判定只放行 **7.7%**，它是实际上在做抑制的那一层
- 而影子说 speak 85.6%，判定点投影要把最忙的群放大 3.9 倍
- 包络还在 shadow 模式，没读过真实拦截率

**先读 shadow 数，再拨 enforce，再谈关 heart。** 顺序反了就是把刹车片拔了再装新的。

### 这一节的方法论价值

四轮里我的两个"数字变好了"方向完全相反：一轮是系统真的变了（身体事实到达），一轮是我的尺子修好了（join 修正）。**区分这两者，只能靠"先验尺子再动手"** —— 而尺子本身也会错，所以每个关键数字都要问一句"这个数的分母是什么"。

投影那一栏里我就犯了第二个错：用 speak/(speak+silent) 算"判定点想要"，而 silent 只有 2 个样本，算出个假的 100%。分母改成全部判定（含 wait/failed）之后才是真实的 86%。

## 九·补二、实施后期新增/修正的物理机制（论文主体未覆盖，2026-09-19 补记）

主体写于设计阶段，下面两个机制是实施过程中**被评审和实测逼出来**的，都不在
原设计里。它们现在都在生产运行，所以必须进论文——否则论文描述的架构和线上
跑的架构不是同一个。

### 补二·A：L0 与睡眠的接口（海床终于知道"在睡"）

原设计的 L0 叫"海床"却完全没有睡眠概念，而睡眠是旧系统里最强的物理约束之一。
缺口不是装饰性的：睡眠时段 bot 读得到每一条消息却一条都回不了，那正是 P 的定义
（"想说而未说出口的冲动存量"）最该积累的时刻，而这段积累原先完全不存在——消息进
pending 队列，醒来时 P=0，bot 像什么都没发生过。

人的行为相反：睡一觉错过一整场对话，醒来头几句话是密的、急的，然后才平缓。

实现（`TRENCH_SLEEP_PULSE_ENABLED`）：睡眠时段读到的人类消息给 P +0.5。

第一版只对 `queued` 的消息触发，实测命中率 **13/1896 = 0.7%**——因为睡眠门用一条
硬规则（`layer==='L2' && !isDirect → silent`）预先判定"这条不值得补看"。但**在睡着的
时候预先判定醒来会想回哪条**，本身就是规则引擎在替模型做判断，这个项目的立场是
把这类判断交回给模型。改为按消息本身计。

代价，**并且纠正我自己在正文里重复过的错误说法**：

> 我曾多次写"繁忙夜（1,883 条 × 0.5）会把 P 钳在 P_MAX=12，醒来时速率先被抬到
> 4.0 条/小时"。**这是错的**，错在只数了注入、没算衰减。

稳态推导（每小时）：
```
注入   0.5H           H = 该群每小时真人消息数
衰减   P → P/2        时间泵半衰期 60 分钟
稳态   P/2 + 0.5H = P  →  P_steady = H
```

所以 **P 会稳定在 H，不会顶格**。要 P=12 需要单群每小时 24 条真人消息——那不是
"繁忙夜"，是轰炸。生产实测印证：P=2.75 的群对应约 2.75 条/小时，此时
r = θ·g(P) ≈ 2.05 条/小时。

> **第三次修正（同日，round 47-48 实测后）**：上面这个稳态**只在不抽气的区间成立**，
> 而且它掩盖了另一种情形。完整图景是三段，不是一段：
>
> | 区间 | 抽气？ | P 的行为 | 实测 |
> |---|---|---|---|
> | 睡眠期 | 无（不说话） | P ≈ 夜间真人速率 | 实验群现 P=0.5，睡一夜预计 1~2 |
> | 白天高峰 | 有（每次发言抽 85%） | 远低于 H | -1004449419602 入站 16/时，P 仅 8.25 |
> | 白天高峰且不抽气 | 无 | H ≥ 12 时会顶格 | 理论上限，实测未出现 |
>
> 关键在第二行：**`releasePressure`（发言抽 85%）是 round 42 才接上线的**，在那之前
> 这个排水路径根本不存在。所以我 round 34 的稳态分析是在"没有主要排水"的系统上做的，
> 它给出的下界偏乐观；而 round 34 之前"繁忙夜必然顶格"的说法偏悲观。两次都错，
> 因为都漏了一个当时还没接线或没在运行的机制。
>
> 这个教训比数字本身重要：**任何关于稳态的结论，都依赖"所有路径都已接线"这个前提**，
> 而这个会话里我已经四次发现某条路径没接线。

这也顺带修正了 Phase 1 的风险评估：醒来时的速率是 **1.4~2.2 条/小时**这个量级
（P≈1~3），不是"顶格 4.0 再泄洪"。我此前把翻旗的风险估得过高，用的是同一个错误
前提。


> **定向债的销账路径比设计时想的窄（round 130 醒来后首次观测）**
>
> 醒来后 20 分钟、6 次回复，**0 次命中债主**，债务总额反而在涨（2.5 / 5 / 9）。
> 原因不是接线坏了（调用点已按生效锚点修好，round 110），而是销账的**结构条件很窄**：
>
> `discharge(chatId, targetUserId, 1)` 只在**带锚点回复某个具体 uid** 时触发。
> 而债主是过夜消息未被回的人——他们现在不一定在说话。于是：
> 1. 债主沉默 → 没有可回复的目标 → 债不动
> 2. 债主再次发言 → bot 可瞄向他，但注意力累加器和心流都偏向**当下活跃者**
> 3. bot 主动发言（无锚点）→ targetUserId 为空 → 不销账
>
> 只有第 2 条能销账，而它要和即时流量竞争。Frame 里那句「还不还、什么时候还，
> **你定**」是诚实的——宿主陈述事实，模型决定。但目前的观测是：**事实被流量盖过**。
>
> **更硬的证据（同轮，逐群比对）**：28 个债主里 10 个醒来后在发言，而——
>
> | 群 | 活跃债主 | 醒来后回复 | 命中 |
> |---|---|---|---|
> | -1004451430063 | 2 人 | 0 次 | 0 |
> | -1003350411234 | 2 人（其中一人发 14 条） | 0 次 | 0 |
> | -1003821093564 | 2 人 | 0 次 | 0 |
> | -1002767093213 | 1 人 | 2 次，对象是另外两人 | 0 |
>
> 唯一有回复那个群里，债主也在说话，bot 回了别人。**债主在场且可得，仍然没被选。**
>
> 这不是 bug，是设计的一个**已测量后果**：定向债让宿主知道欠谁，但不影响模型的
> 选择。要让它真正驱动衰减，需要让债进入**选择**而不只是被看见——两条都可回滚：
> 1. 把欠得最多的群的 θ 抬高一点（气压侧，宿主持有，模型只读）；
> 2. 在注意力累加时给债主加权（选择侧，同样是宿主的确定性规则）。
> 两条都不改模型、都不删机制、都能单独 revert。


### 补二·B：定向债（Debt）—— 让衰减由闭环驱动，不由时钟驱动

多模型评审第 22 轮的反对意见：睡眠积压是**无方向的免费势能**。醒来后 P 饱和，
而压平它的只有 60 分钟半衰期——也就是说衰减由 `Date.now()` 驱动。评审的原话：
由 clamp 顶住的包络天生是痉挛签名。活人醒来的密话有两个特征它没有：每条锚在
夜里堆积的具体人身上；没人接就自己停。

**实现上没有把 P 改成向量。**积分器保持标量（它管速率，数学本身没问题），缺的是
方向，而方向是给模型的信息，不是积分器的状态：

- `src/nyatos/debt.ts`：按 (群, 发送者) 记"欠谁一句"，单笔硬上界 6，TTL 24h
- 睡眠脉冲把同一个 0.5 记两遍：一次进标量 P（管速率），一次进那个发送者的债（管方向）
- 真的回给了锚点那个人 → 销账。**这是衰减改由闭环驱动的兑现点**
- Frame 渲染成债，不是工单队列：

```
[欠话] 你睡着的时候 小美（欠 2 句）——总共欠 3 句。还不还、什么时候还，你定。
```

拿不到昵称就说"那个人"，不编名字。

我自己提过的担忧（"指向性会不会让醒来行为变窄"）在这里得到解答：会窄，而那是对的
——人醒来是回昨晚跟自己说话的人，不是对整个房间发言。

### 补二·C：卡死自恢复（论文约束 4 的生产落地）

约束 4 要求"任何 host 否决器必须可被强制解锁"。而 `resetTrench` 一度只有测试能调
（死代码扫描发现它是 TESTONLY）——等于把 satiation latch 事故（clock 被非权威方刷新
→ 4 天 66 次 veto 无人知）的同一个形状留在了新架构里。

时间泵 cron 现在自动检测并恢复：**P 连续顶在 P_MAX 6 小时以上 → 硬复位 + warn**。
判据是结构性的：P 顶格意味着注入持续压过抽水，而正常聊天不可能（一次发言抽 85%）。

### 补二·D：包络参数改为由投影口径论证

第一版包络参数（150/100 条每小时）是拿**未放大的现状**回测的，结论"拦截 0.1%，
可以直接拨"。那回答的是"碍不碍事"，不是这个包络存在的理由——它要接住的是判定点
扶正后的 3.9 倍放大。

`scripts/envelope-backtest.mts` 现在两个分母都算，判读只用投影：

```
现状 1,844 条 → 拦 1   (0.1%)   ← 错的问题
投影 7,376 条 → 拦 786 (10.7%)  ← 对的问题
```

阶梯（投影 3.9x 下）：150/100 → 10.7% · 200/150 → 5.7% · 250/200 → 3.1% · 300/250 → 1.8%。
保留 150/100：落在评审提出的 5~15% 设计区间里，接得住放大又不至于变成静音。

### 补二·E：Echo 的身体事实曾经没接线

`renderEcho` 从写下起就没接进 Frame（死代码扫描发现它是 TESTONLY），于是 E 在 Redis
里算、在学，模型却从未看见过它。一个观测不到自己回声的人，学不到"我说的话有人接
没人接"——而那正是 L2 存在的全部理由。

补上之后写测试，又在**一个真实群**（E≈0.3-0.5）上抓到第二个缺陷：托底句
（"但这不代表不该说"）只写在最低档，而它防的风险——模型把"没人接"读成"我该闭嘴"
——在每一档低声誉都存在。三档现在都带。

## 九·补三、Phase 1 灰度实验的设计（2026-09-19，翻旗前的最后一道算术）

上两轮把 Phase 1 从"全局翻旗"改成了按群灰度（`META_HEART_BYPASS_CHAT_IDS`，
名单优先于全局开关），并给金丝雀加了分群读数。但在真的往名单里放一个 chatId
之前，还有一道算术必须做：**这个群在旁路下会不会撞包络的上限？**

方法：取该群的峰值入站小时，乘以判定点的 speak 比例（86%，来自 shadow 覆盖群
的实测），与包络的 150 条/小时比较。

| 群 | 峰值入站/时 | 当前发送率 | 86% 投影 | 撞 150 上限？ |
|---|---|---|---|---|
| -1003821093564 | 364 | 22% | **313** | **会，被拦约一半** |
| -1003543275052 | 453 | 21% | 390 | 会（且非 shadow 群，纯外推） |
| -1003184176508 | 112 | 48% | 96 | 不会 |
| -1002750574953 | 37 | 26% | 32 | 不会 |

**这道算术直接否掉了我原本的第一选择。**我一直把 `-1003821093564` 称作"最忙的群"
并以它为 3.9x 投影的对象，但它是三个 shadow 群里唯一会在旁路下撞上限的。在它身上
实验，观察到的不会是"bot 变活泼"，而是"它想回 313 条、被包络拦掉 163 条"——
每一次拦截都会把"你回得太密了"抛回给模型，而那正是评审说的痉挛签名。

**第一个群选 `-1002750574953`**：峰值入站仅 37 条/时，86% 投影 32 条/时，
距 150 上限有 4.7 倍余量；而当前 26% → 10 条/时，所以信号是 3.2 倍，清晰可测。

**预测（跑之前写死，防止事后合理化）**：

基于已实测的三个数——该群 3 天入站 227 / bot 发送 58（=26%）/ 峰值入站 37 条每小时，
以及判定点在 shadow 覆盖群上的 speak 比例 86%：

| 量 | 现值 | 预测 | 超出即说明我的模型错了 |
|---|---|---|---|
| 该群发送率 | 26% | 55%~86% | >90% 或 <40% |
| 峰值小时发送 | ~10 条 | 25~32 条 | >37 条（超过入站量，不可能） |
| 包络拦截数 | 0 | 0（上限 150，投影 32，余量 4.7 倍） | >0 说明上限或投影算错 |
| 其余 7 群曲线 | 各自基线 | 不动（灰度只作用于名单内） | 任何一群动 = 灰度串味 |

> **仪表自测发现的混杂（round 51）**：给金丝雀加了 `--since/--until` 时间窗之后，
> 第一次在实验群上跑就发现「26% 基线」是个会骗人的数——同一群的发送率按小时在
> **21% ~ 74%** 之间跳（19 条入站回 14 条 = 74%）。所以「预测 55~86%」和一个普通
> 忙时的 74% **在数字上分不开**。
>
> 正确对照因此不是「实验群 vs 全站平均」，而是**同群、同时段、不同日期**：
>
> ```
> 实验窗   npx tsx scripts/trench-canary.mts 1 --since HH:MM --until HH:MM
> 对照窗   同一指令，把日期挪到前一天同一时段（需先扩日期参数）
> ```
>
> 在此之前，任何「发送率涨了」的读数都不能归因给旁路——它可能只是那个小时本来就忙。
> 这条混杂如果没被发现，实验会用一个无法归因的数字宣布成功。
>
> 另一个读数方向不受此影响：**包络拦截数**。基线是 0，只要它 >0 就说明行为真的变了
> （因为现有流量从未触发过上限）。那是这个实验里唯一不需要对照组的信号。

两条明确的证伪条件：
1. 若发送率停在 40% 以下 —— 说明旁路了心流也没让判定点接权，问题不在抑制层，
   在我对"决策点想要什么"的建模（86% 那个数来自 shadow 覆盖群，是观测不是定律）。
2. 若包络开始拦截 —— 说明峰值入站的分布比我用"峰值小时"估计的更尖，
   该做的是重测分布，不是调上限去消音。

判据（跑完后照这个读，不跑完不解释）：
- 发送率从 26% 抬到 60% 以上 = 判定点真的接了权
- 包络拦截数 > 0 且持续 = 上限太紧，该调参而不是回滚
- 同群投诉/关系分下降 = 行为退化，回滚
- 其余 7 群曲线不动 = 灰度生效，没有串味

## 九·补四、"单决策点"这个论断比论文说的更不成立（round 54 查发送量暴涨时发现）

核查每日数据时发现一件事：09-18 发送 153 条，**09-19 发送 1,541 条（10 倍）**，
而入站只涨 1.4 倍。追因得到一张比我预想复杂的图：

```
每日     CodeAct任务  burst摄取  burst/任务
09-17        22         0       0.00
09-18        97        12       0.12
09-19       964       279       0.29
```

`same_speaker_burst` 是**第三条绕过心流的路径**（`speaker-burst.ts`）：当 bot 正在
回某个用户、或该用户的 burst 窗口还开着时，他的下一句话被强制按 L0 直接摄进
attention——**不问心流**。

它和任务量构成正反馈：任务越多 → in-flight 越多 → burst 窗口越多 → 强制摄取越多
→ 任务越多。09-19 的 burst 摄取跳了 23 倍，`burst/任务` 从 0.12 涨到 0.29，
就是这条环在自我放大的指纹。（它有上界：`tryClaimBurstOnce(chat, uid, 180)`，
同一用户每 3 分钟最多一次，所以不会发散，但会显著抬高基线。）

**这对论文的"单决策点"论断是个实质修正**：生产里有至少三条路径能在不问心流的情况下
产生 CodeAct 任务——
1. `same_speaker_burst`（bot 正在回你，你的下一句直接进）
2. `post-task continuation`（bot 说完 120 秒内你接了话头 → 绕过 Meta 直接续答）
3. direct / L0（被点到名的消息本就不进心流）

所以 Phase 1 旁路心流时，**这三条路照旧产生任务**。论文里"影子升级为唯一决策点"
这个设计，在实现上要先决定这三条路归谁管——否则旁路心流只会让"绕过心流"的路径占比
更高，而我把观测到的变化误读成"判定点接了权"。

这也是为什么 Phase 1 的判据里必须保留**包络拦截数**这个不需要对照组的信号：
它测的是总量形状，不依赖我归因给哪一层。

**另一个必须先排除的假信号（round 53）**：

`self_replies.trigger_msg_id` 为空的行占 40%（820/2069）——看起来 bot 已经有四成
自发发言。但按时间分层：

```
锚点修复（effectiveAnchor）之前   共 2062   带锚点 60%   无锚点 820
锚点修复之后                     共 7      带锚点 100%  无锚点 0
```

也就是说当前行为是**只在被叫到时说话**，而 host 会为几乎每次发送填 `defaultReplyTo`
（`isAddressed = replyTo ?? defaultReplyTo`）。这同时解释了为什么"6 条/h"的 budget
几乎从不拦人——豁免条件几乎总被满足，真正在管事的是包络。

如果拿"40% 主动"去预测旁路效果，会以为基线已经很高、余量不大。实际相反：基线接近 0%
自发，旁路的可观察空间比那个数字暗示的大得多。

（7 个样本不足以做统计结论，但它与日志侧的独立测量一致：全部 1,572 次群发送都带锚点。）

86% 这个数只对 shadow 覆盖的三个群是实测；用在别的群上是外推，所以第一个群
必须从这三个里选——这也是选 `-1002750574953` 而不选 `-1003543275052` 的原因。

## 九·补五、一次我说错的归因，以及第二个只写不读的流（round 55-56）

Round 55 我发现两条绕过心流的路径（same_speaker_burst / post-task）没有调
`noteLiveOutcome`，于是断言"Phase 2 一致率 40% 有 23% 的结构性样本缺口"。
**那句话是错的**，round 56 核实后纠正：

- 对等度脚本（`decision-equivalence.mts`）用的是 **`shadow_ingress` + `self_replies`**，
  而绕过路径的发送照样经过 `host-api.sendText → recordSelfReply`，
  所以"bot 有没有说"这一侧本来就是完整的。
- `live_outcome` 那个账本**没有任何消费方**（grep 全仓，除写入点外零读取）——
  它和 var/trench.jsonl 是同一类"只写不读的流"，是我这个会话的第六类失败形态。

所以真实情况不是"40% 有缺口"，而是"有另一个无人读取的账本缺了 23% 的记录"。
前者会让我推翻一个本来正确的数字，后者只是少了一份没人看的记录。

但修法没有白做：把绕过路径记成 `intercepted` 之后，我给它配了消费方 ——
金丝雀新增【决策来源】一节。而这个分布立刻暴露第三件事：

```
silent         1313  100%   没说（心流否决）
wait              4    0%   等
spoke             0    0%   ← 从未被记录
intercepted       0    0%   ← 修复后尚未有新事件
```

**`spoke` 从来没有被记过。** 所以这个账本的设计是"记录否决"，与 `self_replies`
（记录实际说了什么）互补 —— 两者合起来才是完整的决策图。这个互补关系此前没有文档，
也没有消费方，所以我 round 55 才会误判它是对等度度量的输入。

## 九·补七、Phase 1 需要几天才可归判（round 4 用历史同期数据算出）

论文一直写"同群同时段不同日期的对照是前置条件"，但没说**要几天**。用已有历史数据
直接算了出来（`scripts/control-baseline.mts` 就是这个采集器，纯只读）。

候选群 `-1002750574953`，同时段（回溯 3 小时窗）各日发送率：

```
09-14 = 33%   09-17 = 0%   09-18 = 14%   09-19 = 50%
均值 24%   σ 19%   极差 50%
```

判据是"25% → 60%+"，效应量 Δ = 36pp = **1.9σ**。按双侧 95%、power 80% 的两样本
均值比较，**每组需约 5 天**。已有基线 4 天，所以还需约 1 天基线 + 5 天实验数据。

顺带算了如果判据放宽会怎样（同一个 σ）：

| 目标 | 效应量 | 需几天/组 |
|---|---|---|
| 40% | 0.8σ | 23 天 |
| 50% | 1.4σ | 9 天 |
| 60% | 1.9σ | **5 天** |

**结论：60% 这个判据不是拍脑袋，它正好落在"5 天能测出来"的位置上；放到 40% 要 23 天，
实际上等于放弃归因。** 这也解释了为什么之前单日读数（0% / 18% / 26%）全不可用——
那些都是一天样本对着 19% 的 σ。

另外，同期方差本身有个来源值得单独记：09-19 那批群**全部偏高**（该群 50%、其它群
15%/30%/25%），而 09-19 正是 `same_speaker_burst` 正反馈被发现的那天。也就是说
σ 里有一部分是 bot 自己的行为漂移，不是群流量波动——这让"同时段不同日期"比
"同日期不同时段"更必要，而不是更没必要。

## 九·补六、定向债"告知而不指挥"—— 一个预先注册的实验（round 132）

醒来后首次观测（round 130-131）给出的已测量结论：**债被 Frame 呈现、被模型看见，
但不进入选择。** 28 个债主里 10 个在场发言，**0 次被选**。

这不是接线问题（销账调用点已按生效锚点修好，round 110），是**债没有进入决策输入**。
设计原话是「还不还、什么时候还，你定」——而现在测得：模型每次都定"不还"。

**候选干预（两条，都是宿主持有的确定性量，都不改模型，都可单独 revert）：**

| 实验 | 落点 | 机制 | 预测 |
|---|---|---|---|
| A 气压侧 | debt 总量 → θ | 群总债越高，该群 θ 越高 → 发言速率上限抬升 | 高债群发言率上升，但**命中债主率不变**（抬的是量不是方向） |
| B 选择侧 | debt → 注意力权重 | 债主的消息在累加时获得固定加成 | 命中债主率上升；若同时发言率暴涨则加成过强 |

**判据（跑之前写死，与 Phase 1 同一格式）：**

- 主判据：**命中债主率** = 窗口内「回复目标 ∈ 该群债主集合」的比例。
  **基线必须与实验用同一个窗口**：醒来后 30-60 分钟的窄窗读数曾低到 **0/13 = 0%**，
  而 1 天窗口实测 **267/1481 = 18%**、3 天窗口 **332/1843 = 18%**（稳定）。
  我一度把窄窗的 0% 当成基线写进论文和仪器 —— 那和第 79 轮那个写死的醒来时间是
  同一类错误：**拿一个窄窗读数当稳态**。
  按 1 天窗口：实验 A 预测 **≤18%**；实验 B 预测 **≥25%**（否则无意义）。
- 反证：若 B 使命中率上升但**总发言率同时翻倍**且关系分下降 → 判为
  "用 Volume 换 Targeting"，回滚。
- 对照组：同时段不同日期的同一批群（与 Phase 1 同一个对照口径）。

**为什么写在这里而不是直接实现**：它和 Phase 1 一样是**生产行为变更**，而且这次连
"该不该让宿主影响选择"都是论文自己提出的开放问题——架构的立场是"宿主只报告嗓子
状态"，而 B 让宿主参与瞄准。这个问题不该由我在无人在场时单方面回答。


## 十、结语：我们到底在换什么

今天的七个子系统都在回答一个问题：**"这条消息该不该回？"** 这是一个**工程问题**，所以它长成了五层判定器、1,754 行闸门、两套并行的心流、和一个零调用方的硬闸。

新架构换掉的是**问题本身**：

> 不是"该不该回这条消息"，而是"**这个群正在发生什么，我在其中想做什么，我的嗓子现在什么状态**"。

前者是分类任务，上限是更准的分类器；后者是**在一个有物理、有历史、有回声的频道里生活**。海沟不给它更好的裁判——它把裁判撤掉，给它一具身体：

- **嗓子**（气压 P / 岸线 θ）——会哑、会饿、说不出话，但永不会消失也永不会嘶鸣不止
- **回声**（Echo E）——它说的话有人接还是没人接，第一次成为可学的信号
- **账本**（cognitive_events）——静默第一次成为一条有 id、有 scope、有结局的行为
- **身体边界**（五条物理约束）——声带发不出电信号，这不是压抑，是生理学

创始人那句话——"不是打造一个助手，而是一个可以看作活生生的人"——在海沟里的工程含义是：

> **克制不是它学到的规则，是它感觉到的累。**
> 牵挂不是它排的队列，是它心里悬着的事。
> 沉默不是它被判为 no_action，是它选择滑过去并承担后果。

这些东西今天一行都写不出来，不是因为我们的 prompt 不够好，是因为**今天的架构里没有一个地方能容纳它们**。海沟就是那个地方。

**而它最激进的承诺是：我们不再预设它该多话该安静。给它嗓子、回声和账本，然后看它在群里活成什么样。**

> **这句话需要打个折（round 69 自查）**：它比实际发生的更激进。
>
> 我确实**移走了一批预设**（喵尾巴规则引擎、6 条/小时的手写阈值、gate 的 LLM 裁决），
> 但我也**放进了新的预设**，而且它们和旧的一样是数字：
>
> | 预设 | 值 | 来源 |
> |---|---|---|
> | 岸线 θ | 4.0（硬钳上限，第一期冻结） | 拍的 |
> | 包络 | 被叫到 150 / 主动 100 条每小时 | 回测拟合 |
> | 气压上界 P_MAX | 12 | 拍的 |
> | 睡眠排程 | 动态但仍是排程 | 既有机制 |
>
> 真实的变化不是"不再预设"，而是**预设从心理层移到了物理层**：
> 它们现在是宿主持有的、模型看得见但改不了的量，而不是写在规则里替模型做的判断。
> 这更好（论文 §三 的立场），但不是"无预设"。
>
> 而"看它在群里活成什么样"这句话，**至今没有执行过** —— Phase 1 实验未跑，
> 所以我还没有资格说我看过。
