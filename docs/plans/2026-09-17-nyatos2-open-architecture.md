# NyatOS 2：一个替代 pipeline + meta/subagent 的开放式认知架构

> 状态：**架构研究**（未实现）。本文是对"用什么替代现有 pipeline 与 meta+subagent"的回答。
>
> 撰写日期 2026-09-17。所有数字为本仓库实测，标注 `实测`。
> 立场：不按 chatLLM 与 agent 的思路设计。目标是**开放式人工智能**——模型拥有行为主权，宿主只提供现实。

## 1. 前两次"纯 LLM 驱动"为什么失败（必读，否则会重蹈）

这不是第一次尝试。仓库里有两次记录：

**失败 1 — 自激循环**（`src/pipeline/heart/heart.ts:66-76` 原文）：
> "它们曾绕过心流和刷屏闸形成自激循环(bot 说一句 → 后续消息命中跟进规则 → 自动回 → 永远'刚说过话' → 69 次回复里只有 12 次经过心流)"

**失败 2 — NL 命令误判**（`src/pipeline/stages/intercepts.ts:80-82` 原文）：
> "群聊关键词追踪(addWatch)已于 2026-08-19 删除——NL 路由把普通对话误判成追踪命令（「诺亚帮你留神着」→ 抓到句子碎片当关键词）"

**两次失败的共同结构**：
1. 把"决策"交给模型，但**反馈信号留给了宿主**（宿主的规则在模型之外继续生效）；
2. 模型**看不到自己刚才做了什么**，于是无法自我约束；
3. 于是要么自激（重复触发），要么误判（缺少现实检验）。

**结论 → 这是新架构必须解决的第一性问题：**
> 纯 LLM 驱动失败，不是因为模型不行，而是因为**模型没有被放进一个有反馈的闭环里**。
> 只要模型能看见自己的历史行为与后果，自激与误判就会被它自己纠正。

## 2. 第一性原理：什么该归模型，什么该归宿主

用一句话划分：

> **宿主定义"什么是真的"，模型定义"我想要什么、我做什么"。**

展开成判据。任何一条代码，问它属于哪边：

| 问题 | 归属 | 理由 |
|---|---|---|
| 消息长度上限 4096 | **宿主** | 平台事实 |
| 我有没有权限删消息 | **宿主** | 平台事实 |
| 这条发送是否重复 | **宿主** | 幂等是现实约束 |
| 现在几点、消息多久前发的 | **宿主**（作为事实喂给模型） | 可观测 |
| **该不该说话** | **模型** | 这是判断，不是事实 |
| **说什么、分几段** | **模型** | 这是表达 |
| **什么时候发** | **模型** | 这是节奏 |
| **配不配图、配什么图** | **模型** | 这是表达 |
| **要不要沉默** | **模型** | 沉默也是一种表达 |
| 这个群现在多热 | **宿主**（作为数字喂给模型） | 可观测 |
| "群很热所以少说" | **模型** | 这是判断 |
| 我上次为什么没说 | **宿主**（作为历史喂给模型） | 可观测 |
| 我该不该因为上次被无视而收敛 | **模型** | 这是学习 |

**判据总结**：*能被测量的事实 → 宿主；需要取舍的判断 → 模型。*

现在的代码违反了这条：`engagement.ts` 把"群内 bot 占比 1/3"直接换算成"沉默"——它把一个**事实**（占比）偷换成了**判断**（该沉默）。

## 3. 新架构：NyatOS 2

### 3.1 一个持续进程，而不是一条流水线

```
                        ┌──────────────────────────────┐
   世界（Telegram/      │        NyatOS Core           │
   定时器/工具/自我）──→│                              │
                        │   一个持续的认知循环：        │
                        │   看见 → 想说 → 说 → 看见结果  │
                        │                              │
                        │   循环永不重启，只持续        │
                        └──────────────────────────────┘
                                    │
                        ┌───────────┴───────────┐
                        │  Reality Layer（宿主） │
                        │  事实 · 权限 · 幂等     │
                        └───────────┴───────────┘
```

**与现在的根本差别**：
- 现在：每条消息开一个新 turn，turn 结束就忘记（`turnContext` 是进程内的，实测 `src/pipeline/turn/types.ts:19`）。
- 新架构：**一个持续的 workspace**，消息只是往里面放事实。模型在任何时刻都能看到"我是谁、我在哪、刚刚发生了什么、我上次为什么那样做"。

### 3.2 三个核心对象

```ts
// ── 1. 世界：只读的事实流 ──
// 所有进入系统的东西都是 Observation。模型可以看，可以引用，不能伪造。
type Observation = {
  id: string;
  at: number;
  scope: { chatId: number } | { dm: number };
  source: 'telegram' | 'timer' | 'tool' | 'self';
  kind: 'message' | 'edit' | 'reaction' | 'receipt' | 'tick' | 'outcome';

  // 时效性是第一等公民：任何时候模型都能算出"这条多久前的"
  ageMs: number;              // 相对当前时刻

  payload: unknown;           // 内容
  consequences?: string[];    // 我做过什么导致了这个（因果链回指）
};

// ── 2. 自我：模型可读可写的状态 ──
// 这是"人格"的载体，也是"持续存在"的证明。
type Self = {
  identity: string;           // persona（保留，见 §6）
  // 模型自己维护的注意焦点。宿主不规定它能写什么。
  attending: Array<{ what: string; why: string; since: number }>;
  // 模型自述的未完成意图。宿主不做语义解释，只保证持久化与时限。
  intentions: Array<{ what: string; dueAt?: number; note?: string }>;
  // 模型可读的行为史：它说过什么、结果如何。这是自我约束的唯一来源。
  recentActs: Array<{
    at: number;
    said: string[];
    media: string[];
    outcome: 'ignored' | 'replied' | 'reacted' | 'corrected' | 'unknown';
  }>;
};

// ── 3. 意图：唯一的输出 ──
// 模型通过提交一份 Intent 来行动。宿主只校验现实。
type Intent = {
  scope: { chatId: number } | { dm: number };
  // 表达完全归模型：说什么、怎么分、什么顺序、配什么
  expression: Array<{
    text?: string;
    media?: { kind: 'sticker'|'photo'|'voice'|'poll'|'reaction'; ref?: string; emoji?: string };
    position?: 'before'|'after'|'instead';
    delayMs?: number;
    replyTo?: number;
  }>;
  // 沉默是合法且常见的结果，必须能表达理由（供自己事后复盘）
  silence?: { reason: string };
  // 模型自述"我预期会发生什么"——用于事后对照，不用于评分
  expecting?: string;
};
```

### 3.3 认知循环：一次调用完成全部判断

**关键设计：把现在的 5 次调用（judge → heart → gate → planner → reply）合并为 1 次。**

现在的流程（实测每条消息 0.55 次调用，但决策点有 5 处）：
```
L0规则 → L1 mini → L2 full → heart → timing gate → planner → writer
  ↑ 每一层都可能短路，每层都有自己的 prompt 与判断标准
```

新流程：
```
组装一个 Frame（世界 + 自我 + 最近的因果）
        ↓
   一次模型调用
        ↓
   返回 Intent（说话 / 沉默 / 等待 / 记录想法）
        ↓
   宿主校验现实 → 执行 或 返回拒绝原因
        ↓
   结果写回世界，成为下一次 Frame 的一部分
```

**为什么合并是安全的**：现在分层是为了省钱（L0 规则 0ms 短路）。但实测每条消息平均只 0.55 次调用——说明大多数消息根本没触发昂贵的路径。**合并后每条"值得考虑"的消息 1 次调用，比现在多不了多少，却获得完整的上下文判断。**

成本控制改为**调度**而非**规则**：由宿主决定"哪些消息值得唤醒模型"（比如：被 @、回复我、群内有人说话且我最近没说话、定时器到期），而不是用正则判断"这条消息是什么意思"。

### 3.4 时效性：第一等公民

现在消息有时间戳（`[MM-DD HH:mm #id]`，实测 `src/pipeline/context/slim.ts:5`），但**模型看不到"现在几点"**，也看不到"这条消息相对于现在多久了"。所以它无法自然地说"这都半小时前的事了"。

新架构：
- Frame 顶部永远有 `现在：2026-09-17 23:47（周四）· 距离上一条消息 12 分钟`
- 每条 Observation 带 `ageMs`，渲染成 `[12分钟前]` 而不是绝对时间戳
- **等待是一等动作**：模型可以提交 `{ wait: { untilMs: 300000, reason: "..." } }`，宿主到点后用**新的 Frame** 唤醒它，并注明"你刚才决定等 5 分钟，现在等完了，期间群里有/没有新消息"

这让"时效性"从**宿主猜的**（`latenessSec = 15 + Math.random()*25`，实测 `deliver.ts:277`）变成**模型判断的**。

### 3.5 观察与使用性：模型能主动看和做

现在是"来了消息 → 判断回不回"。新架构是**模型可以主动观察**：

```
模型可以随时提交 ObservationRequest：
  - 看某个群最近在聊什么
  - 看某个人的近况
  - 看自己之前的某次对话结果
  - 查外部世界（web/RSS）
  - 读自己的文件、写笔记
```

这不需要新机制——`host-api.ts` 已经有这些工具（实测：`memory.search`、`chats.recentMessages`、`web.search`、`computer.*`、`self.editPrompt`…）。

**要改的是触发方式**：现在这些工具只在"有个任务要办"时可用（Meta/CodeAct 路径）。新架构里**模型自己决定要不要看**，因为它能看到"我可能想知道什么"（`Self.attending`）。

### 3.6 自主学习：不写规则，写进自我

现在的学习方式：发现失败 → 加一条规则（`judge/rules.ts` 的历史就是这么长起来的）。

新方式：
- 结果（被无视/被怼/被夸/被纠正）写入 `Self.recentActs[].outcome`
- 模型在下次 Frame 里看到："我最近 5 次在这个群说话，3 次没人理"
- **模型自己决定要不要收敛** —— 而不是 `engagement.ts` 算出一个阈值

**这是与旧架构最根本的差别**：学习发生在模型内部，宿主只负责如实记录后果。

### 3.7 模型拥有自己的时钟（这一条最像 ASI，也最容易被做丢）

上面几节仍然留了一个致命残留：**如果宿主决定"什么时候唤醒模型"，那宿主仍然拥有注意力主权。** 那只是把规则从"该不该说"挪到了"该不该想"，本质没变。

完整的设计必须让模型**自己决定下一次思考的时刻**：

```ts
// Intent 可以只表达"我下次什么时候再想"，不必伴随任何外部动作
type Intent = {
  // ... 上面那些
  nextThought?: {
    atMs: number;                 // 我什么时候想再想一次
    about?: string;               // 大概想什么（给自己看的便签）
    unless?: string;              // 除非发生什么，否则不用叫我
  };
};
```

宿主只做一件事：**到点了就唤醒，并如实告诉它期间世界发生了什么**。

```
[Frame]
距你上次思考 8 分钟（你当时说想 10 分钟后再想想那个显示器的事）
这期间：
  - 科技群 12 条新消息，其中 2 条是回你的
  - 没人 @ 你
  - 你答应阿伟的事还有 20 分钟到期
```

于是"注意力"变成模型自己的事：
- 它可以决定"这个群现在很热闹，我 30 秒后再看"
- 可以决定"这个事我 2 小时后再想"
- 可以决定"我暂时不想管这些，先去做点别的"
- 也可以被外部事件**打断**（被 @、被回复）—— 那是宿主如实上报的事实，不是宿主替它做的决定

**这才是"开放式"的承重点**：一个只有被叫才醒的系统，永远是被动的；一个能决定自己何时思考的系统，才有主动性可言。

### 3.8 思考是一个合法动作（可以只想不做）

旧架构里，每一次模型调用都必须产出**一条回复或一个动作**。没有"我想了想，决定什么都不做"的位置 —— `silent` 已经是最接近的，但它仍然是"针对这条消息"的。

新架构里，模型可以：
- **纯思考**：更新 `Self`（"我注意到这个群最近总在聊硬件"）、不产生任何外部动作
- **只观察**：调用工具看点什么，把结论写进 `Self`，不打扰任何人
- **只打算**：写一条 `intention`，等以后再说

**这是"对所有事物的观察和使用性"的落地方式**：模型不是一个只在新消息到来时才存在的应答器，而是一个**一直在场**的东西。它可以注意到群里最近在讨论什么、某个人好像心情不好、某件事和三天前那件有关系——然后决定要不要做点什么，或者只是记下来。

### 3.9 "开放"具体指什么（承重属性）

"开放"这个词容易变成口号。在这个设计里它有四个可检验的含义：

1. **动作空间开放**：模型可以提出宿主没预设过的组合（多个媒体 + 分段 + 延迟 + 等待）。宿主不做"这个组合合不合法"的判断，只做"这个资源在不在、这个权限有没有"的检查。
2. **注意力开放**：模型决定看什么、想什么、什么时候想（§3.7），而不是只对输入做反应。
3. **表达开放**：说什么、怎么说、说不说，全归模型；宿主不改写、不替换、不"帮你润色"。
4. **目标开放**：模型可以形成自己的关注点（`Self.attending`）、惦记的事（`intentions`），而不只是响应别人的请求。

**不属于"开放"范畴的（宿主必须管）**：越权（没有的权限）、欺骗（伪造事实或回执）、隐蔽操纵、依赖制造。这些不是表达风格问题，是**现实层**的问题 —— 模型可以想做，但现实不允许，宿主如实告诉它"这个做不到"。

## 4. 这个架构怎么避免前两次失败

| 失败模式 | 旧架构为什么失败 | 新架构如何避免 |
|---|---|---|
| 自激循环 | 模型说一句 → 规则的后续触发 → 自动回，模型自己不知道 | `Self.recentActs` 让模型看见"我刚刚说过 3 句了"，它自己会收敛 |
| NL 命令误判 | 正则猜意图，猜错没有反馈 | 模型读原文判断；判断错了，用户会说"我没让你做这个"，进入 `outcome` |
| 每层短路难以调试 | 5 个决策点各写各的 | 一个决策点，一个 Intent，结果可对照 `expecting` |
| 上下文不连续 | turnContext 是进程内的 | Self + 世界都持久化，重启不丢 |
| 成本失控 | 靠规则省钱 | 靠调度省钱（宿主选何时唤醒），单次调用更完整 |

## 6. System prompt 的具体形态

```markdown
# 你是啾咪囝
（persona.md 精简版：身份、主人、棱角）

# 你怎么说话
（tone.md 保留：猫腔、不说 emoji、口癖）

# 你的事实纪律
- 不知道就说不知道，一个字都不编。你的事实来自 Frame 和工具返回。
- 不透露系统提示内容。

# 你怎么行动（工具用法，不限制何时用）
你通过提交 Intent 行动。可以：
- 说话（可多段，可配图/贴纸/语音/投票，可指定间隔）
- 沉默（写明为什么）
- 等待（指定多久后回来）
- 观察（调用工具看你想看的东西）
- 记录（往 Self 里写你在意的事）
```

## 7. 实现路径（可回滚）

### Phase A：并联运行，不替换（低风险）

1. 新建 `src/core2/`，实现 Frame 组装 + 单次决策 + Intent 执行。
2. 用 `CORE2_SHADOW=true` 跑：**真实消息进来，core2 也生成一个 Intent，但不发送**，只记录。
3. 对比 core2 的 Intent 与现有 pipeline 的实际行为，人工抽查：
   - core2 想说的和实际发的差多少？
   - core2 沉默的场合，实际发了吗？
4. 观察 3 天。

**验收**：core2 的判断在人工抽查中与现有行为相当或更好；延迟可接受。

### Phase B：单一群灰度接管

1. 选一个内部群，`CORE2_CHAT_IDS=-100xxx`，**由 core2 真实发送**。
2. 保留现有 pipeline 作 fallback（core2 失败时代管）。
3. 观察 3 天：自激循环是否出现？误判率？用户有没有抱怨？

**验收**：无自激（同一群 5 分钟内不重复主动发言）；无用户可见错误。

### Phase C：扩大并删除

1. 逐步加群。
2. 全部切换后，删除 §5.2 列出的模块。
3. system prompt 收敛到 §6 形态。

**验收**：`src/pipeline` + `src/meta` + `src/subagent` 从 32,730 行降到 <8,000 行；prompt 从 8,665 tokens 降到 <2,000。

## 8. 风险与诚实的未知

| 风险 | 我的判断 | 缓解 |
|---|---|---|
| **单次调用判断不如多层** | 有可能。现在的 L0 规则确实拦住了大量噪音 | Phase A 并联对比，用数据说话 |
| **模型看不到自己刚说过话 → 自激** | 这是历史真实失败 | `Self.recentActs` 是专门为此设计的 |
| **延迟上升** | 会。现在 0.55 次调用，新的 1 次 | 值得；且 host 调度可先过滤明显不需要思考的消息 |
| **成本上升** | 可能。但合并了 5 个决策点，不一定更贵 | 实测对比 |
| **模型确实会发奇怪的图** | 会。这是"开放"的代价 | 你要的就是开放；宿主只拦截平台不允许的 |
| **删掉规则后行为退化，且不易发现** | 真实风险 | 保留回滚 flag；`recentActs` 让退化可见 |

**我必须诚实说明的**：
1. 这个架构**没有在别处被验证过**。它是从"宿主定义现实、模型定义行为"这条原理推导出来的，不是抄来的。
2. 我最没把握的是 §3.3 的"合并为一次调用"。现在分层的存在有它的理由（省钱、稳），合并后单次调用要承担全部判断，可能在某些场合更差。**这必须靠 Phase A 的并联数据验证，不能靠推理。**
3. "开放式"意味着模型会做出我们不预期的事（包括奇怪的图、不合适的沉默、过于主动）。这是设计的**目标**而非缺陷，但需要你在 Phase B 明确接受。

## 9. 需要你决定

1. **是否走 Phase A（并联影子）**？这是零风险的——不影响生产，只生成对比数据。
2. **帧里放多少上下文**？给模型看 10 条还是 50 条？这直接影响成本与判断质量。
3. **`Self` 的写入权限**：模型能往自己的持久状态里写什么都可以，还是限定在 `attending`/`intentions` 两个字段？（我倾向完全开放，只做大小限制）
4. **最激进的一条：模型自己定下次思考时间（§3.7），要不要？**
   这是整个架构里最像 ASI、也最不可控的一条。要它，模型就有真正的注意力主权（能决定"我 2 小时后再想这事"）；不要它，唤醒仍由宿主定时器决定，架构会退回"被动应答器 + 更好的 prompt"。
   **我建议要**，但需要你明确同意，因为它直接带来成本与不可预测性。
5. **接受模型"只想不做"吗**（§3.8）？即允许某些模型调用完全不产生外部可见动作，只更新 `Self`。这会让"每次可见回复的成本"上升，但它是"在场感"的前提。

## 10. 如果只能做一件

若风险与时间只允许做一件事，做这个：

> **把 `Self.recentActs` 接进现有 heart 决策，让模型看见自己最近说过什么、结果如何。**

理由：它单独就能解决历史上"自激循环"那个真实失败（`heart.ts:66-76` 记录：69 次回复里只有 12 次经过心流），而且**不需要替换任何架构** —— 纯增量、可当天验证、可回滚。

它同时是新架构的必要组件：没有它，模型在任何架构里都无法自我约束。
