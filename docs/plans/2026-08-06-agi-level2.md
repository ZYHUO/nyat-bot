# AGI Level 2: 自主行动 + 纯 LLM 驱动 (2026-08-06)

> **For Hermes:** Phase A（自主行动）是核心新功能；Phase B（纯 LLM 驱动）按"决策启发式消灭、协议性基础设施保留"原则执行。每阶段验证 + 部署。

**Goal:** bot 达到真·自主 AGI：
- 无聊了 → 自己决定"想写点什么玩"→ 进 sandbox 写 Python/Go 项目 → 不会的 web search (Google) / 求助群友 → 完成交付
- 所有**决策**由 LLM 做出，无正则/概率/阈值启发式

**审计结论（2026-08-06）：**
- ✅ 已 LLM 驱动：Heart decision（reply/wait/pass 一颗心）、reply 层（agentic tools + LLM 工具选择）、CodeAct 统一执行
- 🔴 残留规则引擎：`judge/rules.ts` 启发式（hot_chat 概率、active_conv_engage、recent_reply 冷却）、`classify-layer.ts` L1 正则、`path-patterns.ts` 搜索意图正则、`reply-context.ts` isShortFollowUpText 正则、`talk-value.ts` 频率闸
- 🔒 协议性基础设施（保留）：@/昵称/命令检测、DM 判定、防重复状态机（speaker-burst）、频率闸（成本保护）

## Phase A — 自主行动 Self-Play（核心新功能）

### Task A0: sandbox 运行时环境

**Objective:** sandbox 里 python3/go 可用，模型能查询可用环境。

**Files:**
- Modify: `src/sandbox/terminal.ts` 加 `computer.env()` → 返回 `{ python: version, go: version, node: version }`
- Modify: `src/subagent/host-api.ts` `buildComputerApi` 加 `env()` 方法
- Modify: `src/subagent/executor.ts` EXECUTOR_SYSTEM 加 `computer.env()` 文档
- Shell: 安装 Go（`apt-get install -y golang-go`），确认 python3 在 PATH

**验证:** `computer.env()` 返回三个运行时版本；`computer.run('python3 --version')` / `computer.run('go version')` 成功。

### Task A1: self-play.ts — 自主决策模块

**Objective:** cron 定时让模型自主决定"现在想不想找点事做、做什么"。

**Files:**
- Create: `src/cron/self-play.ts`
- Modify: `src/env.ts`（SELF_PLAY_ENABLED / INTERVAL_MIN / MIN_IDLE_SEC / USAGE）
- Modify: `src/cron/scheduler.ts`（注册 cron）

**设计：**
```typescript
interface SelfPlayVerdict {
  play: boolean;
  idea: string;        // 想做的事（写个小工具/学个新东西/做个实验）
  plan: string[];      // 2-5 步计划
  reason: string;
}
```
- cron 每 `SELF_PLAY_INTERVAL_MIN`（60）跑
- 前置条件：主人 DM 和活跃群沉默 > `SELF_PLAY_MIN_IDLE_SEC`（2h）——不打扰真人时自己玩
- LLM prompt：综合"上次玩了什么、最近聊过什么、当前时段、心情"→ 自主决定 play 与否
- play=true → dispatch CodeAct 任务（复用 taskToGroup / enqueueCodeActJob，mode=work 语义）
- **记忆**：Redis `xxb:selfplay:last:{idea_hash}` 防重复；`xxb:selfplay:history` 记录玩过什么

**验证:** 日志出现 `Self-play: decided to play <idea>` / `stay quiet`；CodeAct 任务被 dispatch。

### Task A2: self-play 执行 prompt（self-play.md）

**Objective:** 模型在 self-play 任务里自主"写→跑→验证→迭代→交付"。

**Files:**
- Create: `prompts/task/self-play.md`
- Modify: `src/subagent/executor.ts` — self-play 任务（contentDirection 带 `[selfplay]` 标记）加载此 prompt

**prompt 要点：**
- 你是自主的 AI——主人不在时你自己找事做
- 流程：Think 计划 → computer.run/python3 写代码 → 运行验证 → 不满意就迭代 → 完成
- **不会就搜**：卡住 → `web.search`（Google 风格查询）→ 消化再试
- **求助群友**：搜不到 → `telegram.sendText` 在活跃群发问（自然口吻，如"有人知道 X 怎么搞吗"），等回复时先做别的
- 完成 → 产物存 sandbox，`sendText` 简短汇报（做了什么、放哪了）；主人相关才 sendFile
- 探索新东西：可以学新库/新语言特性，做小实验，写工具脚本

**验证:** 部署后观察 self-play CodeAct 会话真实执行多步。

### Task A3: web search 升级（Google 可及性）

**Objective:** 确认 web.search 底层能搜到 Google 结果。

**Files:**
- Inspect: `src/pipeline/tools/search.ts`（现状是 Gemini/xAI/Searx/DDG）
- 若 DDG 被墙 → 换 Searx 公共实例或配置 Google Custom Search；确认可用

**验证:** `web.search('golang 教程')` 返回真实结果。

### Task A4: 求助群友链路

**Objective:** self-play 卡住时能自然地在群里问。

**设计：**
- prompt 已含求助指引（A2）
- 技术验证：`telegram.sendText` 在群发问不违反防刷屏（self-play 频率低，天然安全）
- 群友回复 → 走正常 Attention → bot 继续任务（可选：把回复转成 self-play 续跑）

**验证:** 观察日志，卡住时出现群内提问。

## Phase B — 纯 LLM 驱动（消灭决策启发式）

### Task B1: classify-layer.ts 简化

**Objective:** 分层交给 LLM/Heart，只留协议性判定。

**Files:**
- Modify: `src/meta/classify-layer.ts`
- 删除 L1 正则（QUESTION_MARK/QUESTION_CUES 判断）——被动消息一律 L2，由 Heart LLM 决定是否插话
- 保留：DM→L0、isDirect→L0（协议性）

**验证:** typecheck + 既有测试更新；被动问题消息仍由 Heart 正确响应。

### Task B2: path-patterns.ts 意图正则下线

**Objective:** "要不要外部查询"交给 LLM。

**Files:**
- Modify: `src/pipeline/judge/rules.ts` — 移除 `looksLikeExternalLookupRequest` / `looksLikeFollowupLookupRequest` 调用点
- Modify: `src/pipeline/path-patterns.ts` — 标记 deprecated（保留导出避免破坏 import，但不再用于决策）
- reply 层已有 agentic tools（LLM 决定搜不搜）+ Heart lookup path，天然覆盖

**验证:** typecheck + 测试；"查一下天气"仍能触发搜索（走 LLM 工具决策）。

### Task B3: rules.ts 启发式下线

**Objective:** 概率/冷却启发式交给 LLM。

**Files:**
- Modify: `src/pipeline/judge/rules.ts`
- 删除/降级：hot_chat 概率跳过（30/70/100%）、active_conv_engage 0.6 概率、recent_reply 冷却、bot_fatigue 轮数限制
- **保留**（协议性）：@/昵称、命令白名单、DM、转发、reply_to_self
- 未命中规则 → 直接 fallthrough 到 Heart（LLM）判断——被动消息本来就走 Heart

**验证:** 全量测试；热群行为由 Heart LLM 克制（prompt 已有"别刷屏"人格）。

### Task B4: reply-context.ts 语义正则弱化

**Objective:** isShortFollowUpText 从"决策"降级为"prompt 提示"。

**Files:**
- Modify: `src/meta/reply-context.ts` — isBarePingText（格式检测，协议保留）；isShortFollowUpText 保留（它只影响 prompt 拼接提示，不直接决策回复，属合理上下文增强）

**验证:** 无行为回归。

### Task B5: talk-value.ts 评估

**Objective:** 频率闸定位为"成本保护"而非"意图引擎"，保留但注释明确。

**Files:**
- Modify: `src/pipeline/timing/talk-value.ts` — 头部注释明确：这不是意图规则，是 MaiBot 成本闸（防每条消息都烧 LLM gate）；纯 LLM 驱动不等于无成本控制

**验证:** 无行为变化。

### Task B6: 全库规则引擎审计

**Objective:** grep 所有正则/概率/阈值决策点，确认无漏网。

**Files:**

- 逐个标注：协议（保留）/ 成本（保留）/ 意图（LLM 化）
- 输出审计清单到 `docs/plans/2026-08-06-agi-level2.md` 附录

**验证:** 审计清单完整，无未评估的决策规则。

| 位置 | 说明 |

| `speaker-burst.ts` | Redis 状态机，防重复回复（TOCTOU 已用 Lua CAS） |
| `classify-layer.ts` DM/@ → L0 | 协议事实 |

### 🔒 保留：成本保护（非意图引擎）
| 位置 | 说明 |
|------|------|
| `talk-value.ts` | MaiBot 频率闸——攒够消息才调 gate LLM。意图判断仍在 LLM |
| `self-continue.ts` 概率门 | 触发"是否 LLM 补一拍"的成本/拟人化随机闸；生成内容由 LLM 决定 |
| `idle.ts` / `proactive-scan.ts` 概率闸 | 在 LLM 决策（persona 生成/shouldChimeIn）之后的二次拟人化随机 |

### 🔒 保留：表达风格随机（不是意图决策）
| 位置 | 说明 |
|------|------|
| `humanizer.ts` 全部 | 错字/口癖/emoji/前缀/思考插入——真人说话就有随机性 |
| `deliver.ts` 打字延迟/幽灵输入 | 拟人化时序（人类打字速度随机） |
| `segmenter.ts` 句号/合并概率 | 群语言习惯的表达风格 |
| `reactions.ts` / `peer-reaction.ts` | 加 reaction 的真人随机性 |
| `gacha/guess-number/checkin/fate` | 游戏/功能需求 |
| `sleep.ts` 随机 | 睡眠状态拟人化 |

### 结论
**意图决策（该不该回/该不该说/该不该搜）已 100% LLM 化。** 剩余的规则/随机全部是：协议性事实（@/命令/防重复）、成本保护（频率闸）、表达风格（拟人化随机）——这些不属于"规则引擎"，删除它们会导致 bot 刷屏/死循环/机械感，而非更智能。
