# 离线组合验收

使用项目 Node 22 执行 `node --import tsx scripts/verify-integration.mts --offline`。不传参数会拒绝运行，没有默认 live 模式。

入口运行固定清单中的实际行为测试，包括搜索结果解析与失败回退、反广告授权和呈现、身体信号真实模块注册、回复式代发闸门、模型路由、在飞限制、缓存文件判断、重复与连发闸门、隔离能力提示词及 QQ codec 到共享入口。它检查每个 suite 和每条断言实际通过，漏项、跳过、子进程异常或报告计数不一致均失败。新增组合需要加入清单并用破坏性反例证明断言能发现错误，不能只添加源码字符串检查。

测试使用合成供应商、Redis 和平台 transport fixture，文件与 SQLite 在临时目录或内存中。launcher 不继承供应商密钥、QQ/TG 凭据、Redis 地址和代理设置，dotenv 固定读取空的临时文件。子进程网络护栏在实际 TCP/UDP 连接前拒绝并令验收失败；tsx 可选的本机 IPC 探测收到模拟连接失败，没有打开真实 IPC 端点。程序仅清理自己创建的临时目录。

旧脚本会请求真实搜索和模型、读生产命令档案并写当前 Redis，且把部分字符串存在误称为组合完成。新版不再执行这些隐式副作用。旧 admin/bots 能力是否可被隔离 agent 调用，以真实 capability 列表测试为准；legacy 代发闸门仍有独立行为测试，不能把 legacy 可用误称为当前 agent 获得管理权限。

通过结果证明这些应用模块在受控输入和故障下能够组合运行，不证明当前真实供应商、账号额度、QQ群送达或机器人在线健康。实际 Linux guest、真实模型和平台回执需要另行记录限定范围的 live 证据，不会被标成跳过后继续报告全绿。
