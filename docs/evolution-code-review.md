# 本轮独立审查记录

审查基线为 4a78661475df6047c80132864b6516bb54d901a4。以下是本次变更的实际审查发现和验证边界；发布 SHA、全量结果和恢复结果在最后验收时追加，当前不表示整轮已发布。

| 发现 | 修复与验证 |
|---|---|
| 模型等待或工具执行期间输入被纠正，endTask、waitForUser、checkpoint 仍可能终结旧草稿 | executor 在异步返回、续跑和终态重新检查固定 intent revision；真实 executor 反例覆盖 endTask-only、wait-only 和 30-turn checkpoint，并保留此前实际 ACK |
| 同一 messageId 的旧 Heart 引用覆盖较新的编辑版本 | Attention/session 依据真实当前意图取版本，不依赖数组遍历顺序；逆序输入回归 |
| waiting_user 任务取消后，下一条新请求可能复活旧 checkpoint | 清理历史活跃绑定并 fresh dispatch；取消 fence 当即禁止旧任务外发 |
| promise backstop 异步返回或发送锁等待后可能越过取消检查 | host 在异步两侧及实际动作之前复核，等待 backstop 完成再结算终态；锁后已取消返回 not_sent，零 RPC 不伪称 unknown |
| 已结算消息的真实后续编辑可能被当重放忽略 | 保留终态版本元数据，真实编辑产生新代；旧重放和已取消来源不能复活 |
| 老账号的 wake 可能在换 token 后被重新安排 | 来源账号绑定 wake、去重、查询和投影；实际换账号回归不重标旧事件 |
| 最初的备份模板不兼容 systemd 219 的日历与配置项 | 使用兼容的小时检查，控制器以 UTC+8 的 04:00 判断逻辑日；实际旧版 systemd verify 通过 |
| 停写阶段做压缩会扩大停机窗口 | 停写期冻结未压缩 tar，恢复写者后只压缩副本；真实 capture 回归验证顺序 |
| 原日志工具测试读取共享日志和配置，CI 的结果依赖机器 | 改为临时合成 JSONL、固定时钟、显式离线输入及零联网约束；同时修复真实分母和路径分支错误 |
| 同名模型在异构 CPU 上未必产生兼容向量 | 哈希一致后仍执行数值/检索对照；候选节点不达标，拒绝路由，见 [部署边界](deployment-topology.md) |
| 更换主人配置后，已经排队的后台创作任务仍可能向旧主人发布 | selfplay/dreaming 在领取与实际 RPC 前核对当前主人；换主人与模型等待期间撤销反例通过 |
