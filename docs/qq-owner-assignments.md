# QQ 主人跨群指派

普通 QQ 群消息已经可以经过 Heart 决定回复、等待或略过，不要求先 @ 机器人。
私聊任务的发送范围仍限私聊；需要去另一群时，使用独立的主人指派入口，不能把原任务改绑到群里。

首次使用需应用[迁移 0136](../migrations/0136_onebot_assignments.sql)，并由运维启用以下配置。若已用过 QQ 独立分支的 0134，升级会保留原迁移登记，0136 会复用已有表、授权和回执。

```dotenv
QQ_ASSIGNMENTS_ENABLED=true
QQ_ASSIGNMENT_GROUP_IDS=123456789
ONEBOT_ALLOWED_GROUP_IDS=123456789
```

这里使用真实 QQ 群号。两个名单都必须明确包含目标群，空名单不开放指派。
`ONEBOT_ACCOUNT_ID`、`ONEBOT_OWNER_ID` 和主人私聊入口必须正确配置；目标也必须满足现有
Meta、CodeAct 隔离和激活时间设置。新入口不会修改这些设置或绕过禁言、睡眠、冷却。

主人在 QQ 私聊提出请求后，模型可调用 `chats.previewAssignment`，输入目标群号或群名、模式、
期限和预算；结果包含核实的目标与完整确认命令。群名不唯一、目录不可用或目标不在允许范围时，
不猜目标，也不派发。预览不代表授权已经生效。

主人直接发送确认命令后才执行，例如：

```text
/qq_assign {"target":"123456789","mode":"once"}
/qq_assign {"target":"123456789","mode":"once","text":"大家晚上好"}
/qq_assign {"target":"123456789","mode":"participate","durationSeconds":600,"maxMessages":3}
/qq_assign status <指派ID>
/qq_assign stop <指派ID>
```

只接受主人本人、同 QQ 账号、真实私聊中的新鲜纯文本命令。转发、可识别编辑、附件和混合消息
不能作为确认。模型不能调用提交指派的 RPC，旧的 Telegram 跨群发送接口也没有开放给 QQ。

单次模式最多一个文字气泡；没有指定公开正文时，任务只看目标群近况，合适才说一句，没有合适内容
可以不发。参与模式默认十分钟、最多三个气泡，最长三十分钟、最多五个气泡，跨任务至少间隔三十秒。
参与模式只等待目标群的新消息，不创建轮询或定时自言自语；Heart 仍决定是否值得开口，预算不是发满指标。
已有短消息上限、回复引用范围、重复内容和节奏检查继续有效。@ 和引用只使用目标会话内可核验的身份与消息。

目标任务重新组装目标群上下文，不携带主人私聊历史、引用、私聊用户输入或 checkpoint。
`text` 只表示主人在确认命令中明确同意公开的正文或主题；省略时不复制自然语言私聊请求。
指派任务不能再登记不受期限限制的目标、唤醒或子任务，也不能用媒体、表情绕过文字预算。

授权、命令回执、任务绑定、发送预留和实际发送回执保存在 SQLite。重复命令不重复创建或派发；
发送前原子预留整个气泡计划，每个气泡发送前再检查停止、期限及允许范围。未知结果保留预算并停止
自动重试。查询显示真实回执数量和状态，不返回群正文；“已受理”“已入队”都不等于已经在群里说过话。

停止指派会撤销尚未发送的附加参与，已交给平台的消息无法撤回。明确对机器人说“安静”等停止话语时，
现有纠错冷却也会真正抑制群内回应；群友之间随口说“停”不会自动撤销授权。单纯停止指派不会永久关闭
原有的普通群消息回复功能。

工具未提供、配置未启用、目录或连接不可用、平台明确拒绝和已知禁言/退群是不同状态。
不得把它们一概说成“没有群发言权限”，也不能把“先在群里 @”当作通用授权要求。

本方案依赖现有单一状态 authority。没有实现多个独立 SQLite 写者的协调，也不保证未知投递可恢复为
确定结果。迁移和开关尚未在生产采用；实际 QQ 账号、禁言、发送回执及线上版本仍需在部署环境验收。
